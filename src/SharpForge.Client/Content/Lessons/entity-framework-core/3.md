## Basic Entity Class

This is a plain C# POCO entity class; EF Core maps properties to database columns by convention (Id => primary key).

```csharp
public class Product
{
    public int Id { get; set; }  // Convention: primary key
    public string Name { get; set; } = string.Empty;
    public string? Description { get; set; }
    public decimal Price { get; set; }
    public int Stock { get; set; }
    public DateTime CreatedAt { get; set; }
    public bool IsActive { get; set; }
}
```

## Data Annotations

Data annotations provide a quick way to configure mapping rules directly on entity properties (required, max length, column type, computed/not mapped, etc.).

```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

public class Product
{
    [Key]
    public int Id { get; set; }

    [Required]
    [MaxLength(100)]
    public string Name { get; set; } = string.Empty;

    [MaxLength(500)]
    public string? Description { get; set; }

    [Column(TypeName = "decimal(18,2)")]
    public decimal Price { get; set; }

    [Range(0, int.MaxValue)]
    public int Stock { get; set; }

    [DatabaseGenerated(DatabaseGeneratedOption.Identity)]
    public DateTime CreatedAt { get; set; }

    [NotMapped]  // Not stored in database
    public decimal TotalValue => Price * Stock;
}
```

## Fluent API Configuration

Use the Fluent API in `OnModelCreating` for advanced mapping scenarios; this example shows common property configuration and indexing.

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Product>(entity =>
    {
        entity.ToTable("Products");
        entity.HasKey(e => e.Id);
        
        entity.Property(e => e.Name)
            .IsRequired()
            .HasMaxLength(100);
        
        entity.Property(e => e.Price)
            .HasPrecision(18, 2);
        
        entity.Property(e => e.CreatedAt)
            .HasDefaultValueSql("GETUTCDATE()");
        
        entity.HasIndex(e => e.Name);
        
        entity.Ignore(e => e.TotalValue);  // Not mapped
    });
}
```

## Entity Configuration Classes

Split configuration into classes that implement `IEntityTypeConfiguration<T>` to keep the `DbContext` tidy and modular.

```csharp
public class ProductConfiguration : IEntityTypeConfiguration<Product>
{
    public void Configure(EntityTypeBuilder<Product> builder)
    {
        builder.ToTable("Products");
        builder.HasKey(e => e.Id);
        builder.Property(e => e.Name).IsRequired().HasMaxLength(100);
        builder.Property(e => e.Price).HasPrecision(18, 2);
    }
}

// Apply in OnModelCreating
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.ApplyConfiguration(new ProductConfiguration());
    
    // Or apply all configurations from assembly
    modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);
}
```

## Value Conversions

Value conversions map CLR types to database representations (e.g., enums to strings or lists to CSV); use them when the CLR type doesn't map directly to a DB type.

```csharp
public enum ProductStatus { Draft, Active, Discontinued }

public class Product
{
    public ProductStatus Status { get; set; }
}

// In configuration
builder.Property(e => e.Status)
    .HasConversion<string>();  // Store as string in DB

// Custom conversion
builder.Property(e => e.Tags)
    .HasConversion(
        v => string.Join(',', v),
        v => v.Split(',', StringSplitOptions.RemoveEmptyEntries).ToList());
```
