## Running Multiple Services Locally

A microservices system has many moving parts: services, databases, message brokers, and caches. **Docker Compose** lets you define all of them in a single `docker-compose.yml` file and start everything with one command.

## A Basic Compose File

```yaml
services:
  order-service:
    build:
      context: .
      dockerfile: OrderService/Dockerfile
    ports:
      - "5001:8080"
    environment:
      - ConnectionStrings__OrderDb=Server=order-db;Database=orders;User=sa;Password=YourPass123!;TrustServerCertificate=true
    depends_on:
      order-db:
        condition: service_healthy

  order-db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=YourPass123!
    ports:
      - "1433:1433"
    volumes:
      - order-data:/var/opt/mssql
    healthcheck:
      test: /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "YourPass123!" -C -Q "SELECT 1"
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  order-data:
```

```bash
# Start all services
docker compose up -d

# View logs
docker compose logs -f order-service

# Stop everything
docker compose down

# Stop and remove volumes (clean slate)
docker compose down -v
```

## Multi-Service Example

A more realistic system with multiple microservices and infrastructure:

```yaml
services:
  # --- Application Services ---
  order-service:
    build:
      context: .
      dockerfile: OrderService/Dockerfile
    ports:
      - "5001:8080"
    environment:
      - ConnectionStrings__OrderDb=Server=order-db;Database=orders;User=sa;Password=YourPass123!;TrustServerCertificate=true
      - RabbitMQ__Host=rabbitmq
    depends_on:
      order-db:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy

  inventory-service:
    build:
      context: .
      dockerfile: InventoryService/Dockerfile
    ports:
      - "5002:8080"
    environment:
      - ConnectionStrings__InventoryDb=Host=inventory-db;Database=inventory;Username=postgres;Password=YourPass123!
      - RabbitMQ__Host=rabbitmq
    depends_on:
      inventory-db:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy

  # --- Databases ---
  order-db:
    image: mcr.microsoft.com/mssql/server:2022-latest
    environment:
      - ACCEPT_EULA=Y
      - SA_PASSWORD=YourPass123!
    volumes:
      - order-data:/var/opt/mssql
    healthcheck:
      test: /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "YourPass123!" -C -Q "SELECT 1"
      interval: 10s
      timeout: 5s
      retries: 5

  inventory-db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=YourPass123!
      - POSTGRES_DB=inventory
    volumes:
      - inventory-data:/var/lib/postgresql/data
    healthcheck:
      test: pg_isready -U postgres
      interval: 10s
      timeout: 5s
      retries: 5

  # --- Infrastructure ---
  rabbitmq:
    image: rabbitmq:3-management
    ports:
      - "5672:5672"
      - "15672:15672"
    healthcheck:
      test: rabbitmq-diagnostics -q check_running
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  order-data:
  inventory-data:
```

## Service Discovery with Compose

Services on the same Compose network can reach each other by **service name**. Docker Compose automatically creates a default network for all services in the file.

```csharp
// In OrderService, call InventoryService by service name
var response = await httpClient.GetAsync("http://inventory-service:8080/api/stock/123");
```

## Development Overrides

Use a `docker-compose.override.yml` for development-specific settings like debug ports and bind mounts:

```yaml
# docker-compose.override.yml (automatically loaded)
services:
  order-service:
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
    volumes:
      - ./OrderService:/src/OrderService  # Live code reload
    ports:
      - "5001:8080"
      - "5011:5005"  # Debugger port
```

## Useful Commands

```bash
# Build images without starting
docker compose build

# Start only specific services
docker compose up -d order-service order-db

# Scale a service (run multiple instances)
docker compose up -d --scale order-service=3

# View resource usage
docker compose top

# Restart a single service
docker compose restart order-service
```

## Best Practices

- Use **health checks and `depends_on` conditions** to control startup order
- Store **secrets** in environment variables or Docker secrets, not in the YAML file
- Use **named volumes** for database data so it persists across restarts
- Create a **`docker-compose.override.yml`** for dev-specific config
- Keep the base `docker-compose.yml` close to production settings
- Use Compose for **local development and CI** — use Kubernetes for production
