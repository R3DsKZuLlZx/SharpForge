## Observing Service Health

In a microservices system, services go down, databases become unreachable, and message brokers restart. **Health checks** give the infrastructure visibility into each service's status so it can route traffic away from unhealthy instances and restart stuck processes.

## ASP.NET Core Health Checks

.NET has built-in health check support:

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddHealthChecks();

var app = builder.Build();

app.MapHealthChecks("/health");

app.Run();
```

The `/health` endpoint returns `Healthy`, `Degraded`, or `Unhealthy` with a 200 or 503 status code.

## Checking Dependencies

Add checks for databases, message brokers, and external services:

```bash
dotnet add package AspNetCore.HealthChecks.SqlServer
dotnet add package AspNetCore.HealthChecks.NpgSql
dotnet add package AspNetCore.HealthChecks.Rabbitmq
dotnet add package AspNetCore.HealthChecks.Redis
dotnet add package AspNetCore.HealthChecks.Uris
```

```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(
        builder.Configuration.GetConnectionString("OrderDb")!,
        name: "sql-server",
        tags: ["db", "ready"])
    .AddRabbitMQ(
        builder.Configuration.GetConnectionString("RabbitMQ")!,
        name: "rabbitmq",
        tags: ["messaging", "ready"])
    .AddRedis(
        builder.Configuration.GetConnectionString("Redis")!,
        name: "redis",
        tags: ["cache", "ready"])
    .AddUrlGroup(
        new Uri("http://inventory-service/health"),
        name: "inventory-service",
        tags: ["service", "ready"]);
```

## Liveness vs Readiness Endpoints

```csharp
// Liveness — just checks the process is running
app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false  // No dependency checks
});

// Readiness — checks if the service can handle requests
app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready")
});

// Detailed status for monitoring dashboards
app.MapHealthChecks("/health/detail", new HealthCheckOptions
{
    ResponseWriter = WriteDetailedResponse
});
```

## Detailed Health Response

Return structured JSON for monitoring tools:

```csharp
static Task WriteDetailedResponse(HttpContext context, HealthReport report)
{
    context.Response.ContentType = "application/json";

    var result = new
    {
        status = report.Status.ToString(),
        duration = report.TotalDuration.TotalMilliseconds,
        checks = report.Entries.Select(e => new
        {
            name = e.Key,
            status = e.Value.Status.ToString(),
            duration = e.Value.Duration.TotalMilliseconds,
            description = e.Value.Description,
            exception = e.Value.Exception?.Message
        })
    };

    return context.Response.WriteAsJsonAsync(result);
}
```

Sample response:

```json
{
  "status": "Healthy",
  "duration": 45.2,
  "checks": [
    { "name": "sql-server", "status": "Healthy", "duration": 12.1 },
    { "name": "rabbitmq", "status": "Healthy", "duration": 8.3 },
    { "name": "redis", "status": "Healthy", "duration": 2.1 }
  ]
}
```

## Kubernetes Probe Configuration

```yaml
spec:
  containers:
    - name: order-service
      readinessProbe:
        httpGet:
          path: /health/ready
          port: 8080
        initialDelaySeconds: 5
        periodSeconds: 10
        failureThreshold: 3
      livenessProbe:
        httpGet:
          path: /health/live
          port: 8080
        initialDelaySeconds: 15
        periodSeconds: 30
        failureThreshold: 3
      startupProbe:
        httpGet:
          path: /health/live
          port: 8080
        initialDelaySeconds: 5
        periodSeconds: 5
        failureThreshold: 12
```

## Custom Health Checks

Create your own checks for domain-specific health:

```csharp
public class OrderProcessingHealthCheck : IHealthCheck
{
    private readonly IOrderQueue _queue;

    public OrderProcessingHealthCheck(IOrderQueue queue) => _queue = queue;

    public Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context, CancellationToken ct = default)
    {
        var queueDepth = _queue.GetPendingCount();

        if (queueDepth > 1000)
            return Task.FromResult(HealthCheckResult.Unhealthy(
                $"Order queue depth is {queueDepth} — processing is backed up"));

        if (queueDepth > 100)
            return Task.FromResult(HealthCheckResult.Degraded(
                $"Order queue depth is {queueDepth} — processing is slow"));

        return Task.FromResult(HealthCheckResult.Healthy());
    }
}

builder.Services.AddHealthChecks()
    .AddCheck<OrderProcessingHealthCheck>("order-processing", tags: ["ready"]);
```

## Best Practices

- **Separate liveness and readiness** — liveness should never check dependencies
- Keep **liveness checks fast** — a slow check can cause unnecessary restarts
- Check **all critical dependencies** in the readiness probe
- Use **startup probes** for slow-starting services
- Add a **detailed endpoint** for dashboards and debugging (but don't expose it publicly)
- Set reasonable **timeouts and thresholds** — don't restart on the first hiccup
