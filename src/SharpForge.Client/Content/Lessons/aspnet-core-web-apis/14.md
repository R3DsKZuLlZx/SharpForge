## Protect Your API

Rate limiting controls how many requests a client can make within a time window. It protects your API from abuse, prevents resource exhaustion, and ensures fair access for all consumers. .NET 7+ includes built-in rate limiting middleware.

## Setting Up Rate Limiting

Configure rate limiting in `Program.cs`:

```csharp
using System.Threading.RateLimiting;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;

    options.AddFixedWindowLimiter("fixed", config =>
    {
        config.PermitLimit = 100;
        config.Window = TimeSpan.FromMinutes(1);
        config.QueueLimit = 0;
    });
});

var app = builder.Build();

app.UseRateLimiter();
app.MapControllers();
app.Run();
```

## Limiter Types

### Fixed Window

Counts requests in fixed time intervals. Simple but can allow bursts at window boundaries.

```csharp
options.AddFixedWindowLimiter("fixed", config =>
{
    config.PermitLimit = 100;           // Max 100 requests
    config.Window = TimeSpan.FromMinutes(1);  // Per minute
    config.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
    config.QueueLimit = 0;              // No queuing, reject immediately
});
```

### Sliding Window

Smooths out the burst problem by dividing the window into segments:

```csharp
options.AddSlidingWindowLimiter("sliding", config =>
{
    config.PermitLimit = 100;
    config.Window = TimeSpan.FromMinutes(1);
    config.SegmentsPerWindow = 6;  // 10-second segments
    config.QueueLimit = 10;
});
```

### Token Bucket

Allows controlled bursts. Tokens are added at a steady rate, each request consumes one:

```csharp
options.AddTokenBucketLimiter("token", config =>
{
    config.TokenLimit = 100;           // Max burst size
    config.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
    config.TokensPerPeriod = 20;       // 20 tokens every 10 seconds
    config.QueueLimit = 5;
});
```

### Concurrency

Limits the number of simultaneous requests, not the rate:

```csharp
options.AddConcurrencyLimiter("concurrent", config =>
{
    config.PermitLimit = 10;   // Max 10 concurrent requests
    config.QueueLimit = 25;    // Queue up to 25 waiting requests
});
```

## Applying Limits to Endpoints

Apply rate limits using attributes or endpoint metadata:

```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    [EnableRateLimiting("fixed")]
    public IActionResult GetAll() => Ok();

    [HttpPost]
    [EnableRateLimiting("token")]
    public IActionResult Create(CreateProductRequest request) => Ok();

    [HttpGet("public")]
    [DisableRateLimiting]  // No limits on this endpoint
    public IActionResult PublicEndpoint() => Ok();
}
```

## Per-Client Rate Limiting

Partition limits by client identity so each user gets their own allowance:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddPolicy("per-user", context =>
    {
        var userId = context.User?.FindFirstValue(ClaimTypes.NameIdentifier)
            ?? context.Connection.RemoteIpAddress?.ToString()
            ?? "anonymous";

        return RateLimitPartition.GetFixedWindowLimiter(userId,
            _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 60,
                Window = TimeSpan.FromMinutes(1)
            });
    });
});
```

## Custom Rejection Response

Customize the response when a client is rate limited:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;

    options.OnRejected = async (context, cancellationToken) =>
    {
        context.HttpContext.Response.Headers.RetryAfter = "60";

        await context.HttpContext.Response.WriteAsJsonAsync(new
        {
            error = "Too many requests. Please try again later.",
            retryAfterSeconds = 60
        }, cancellationToken);
    };
});
```

## Best Practices

- Apply **global limits** as a safety net, then **per-endpoint** limits for fine-tuning
- Use **per-client partitioning** so one abusive client doesn't block everyone
- Return a **Retry-After** header so clients know when to try again
- Set **different limits** for read vs write operations
- Monitor rate limit hits — frequent `429` responses may indicate limits are too strict
