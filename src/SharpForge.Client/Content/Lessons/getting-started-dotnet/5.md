## What is NuGet?
NuGet is the package manager for .NET. It's how you add third-party libraries to your projects—everything from JSON serializers to database drivers to logging frameworks.
The official repository at <a href="https://nuget.org" target="_blank">nuget.org</a> hosts over 350,000 packages, making it easy to find solutions for almost any problem.
## Finding Packages
There are several ways to discover NuGet packages:
### NuGet.org Website
Browse <a href="https://nuget.org" target="_blank">nuget.org</a> to search for packages, view documentation, and check download statistics.
### Command Line
```bash
# Search for packages
dotnet package search json

# Search with detailed output
dotnet package search serilog --take 10```

## Adding Packages
Use the <code>dotnet add package</code> command:
```bash
# Add the latest stable version
dotnet add package Newtonsoft.Json

# Add a specific version
dotnet add package Serilog --version 3.1.1

# Add a prerelease version
dotnet add package SomePackage --prerelease

# Add to a specific project
dotnet add src/MyApp/MyApp.csproj package Newtonsoft.Json```
This adds the package to your <code>.csproj</code> file:
```xml
<ItemGroup>
  <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
</ItemGroup>```
## Package Versions
Understanding version numbers helps you manage updates safely:
<div class="version-example">
<div class="version-number">
<span class="major">13</span>.<span class="minor">0</span>.<span class="patch">3</span>
</div>
<div class="version-labels">
<span>Major</span>
<span>Minor</span>
<span>Patch</span>
</div>
</div>
- <strong>Major:</strong> Breaking changes—may require code modifications
- <strong>Minor:</strong> New features, backward compatible
- <strong>Patch:</strong> Bug fixes, backward compatible
### Version Ranges
```xml
<!-- Exact version -->
<PackageReference Include="Pkg" Version="1.2.3" />

<!-- Minimum version -->
<PackageReference Include="Pkg" Version="1.2.3" />

<!-- Floating version (latest patch) -->
<PackageReference Include="Pkg" Version="1.2.*" />

<!-- Range -->
<PackageReference Include="Pkg" Version="[1.0,2.0)" />```
## Managing Packages
### List Installed Packages
```bash
# List all packages in a project
dotnet list package

# List packages for entire solution
dotnet list MySolution.sln package

# Check for outdated packages
dotnet list package --outdated

# Include transitive dependencies
dotnet list package --include-transitive```
### Update Packages
```bash
# Update a specific package
dotnet add package Newtonsoft.Json

# The above command updates to latest if already installed
# There's no explicit "update" command - just add again```
### Remove Packages
```bash
# Remove a package
dotnet remove package Newtonsoft.Json```
## Restoring Packages
When you clone a project or your packages get corrupted, restore them:
```bash
# Restore packages for current project
dotnet restore

# Restore for entire solution
dotnet restore MySolution.sln

# Force restore (ignore cache)
dotnet restore --force```

## Package Sources
By default, NuGet uses nuget.org. You can add additional sources for private packages:
```bash
# List configured sources
dotnet nuget list source

# Add a private source
dotnet nuget add source https://pkgs.mycompany.com/nuget -n MyCompany

# Add with credentials
dotnet nuget add source https://pkgs.mycompany.com/nuget -n MyCompany -u username -p password

# Remove a source
dotnet nuget remove source MyCompany```
### NuGet.Config
Configure sources in a <code>NuGet.Config</code> file for your project:
```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    <add key="MyCompany" value="https://pkgs.mycompany.com/nuget" />
  </packageSources>
</configuration>```
## Central Package Management
For solutions with many projects, centralize version management with <code>Directory.Packages.props</code>:
```xml
<!-- Directory.Packages.props in solution root -->
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>

  <ItemGroup>
    <PackageVersion Include="Newtonsoft.Json" Version="13.0.3" />
    <PackageVersion Include="Serilog" Version="3.1.1" />
    <PackageVersion Include="xunit" Version="2.6.2" />
  </ItemGroup>
</Project>```
Then in your project files, omit the version:
```xml
<!-- Individual .csproj files -->
<ItemGroup>
  <PackageReference Include="Newtonsoft.Json" />
  <PackageReference Include="Serilog" />
</ItemGroup>```
## Security Considerations
<div class="warning-box">
<div class="warning-box-header">
<span>⚠️ Security Best Practices</span>
</div>
- Keep packages updated to get security patches
- Use <code>dotnet list package --vulnerable</code> to check for known vulnerabilities
- Verify package authors and download counts before installing
- Consider using a private feed to control which packages are available
</div>
```bash
# Check for vulnerable packages
dotnet list package --vulnerable

# Check for deprecated packages
dotnet list package --deprecated```
