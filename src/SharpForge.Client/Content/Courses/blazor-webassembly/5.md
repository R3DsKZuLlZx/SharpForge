## Handling DOM Events

The following examples show how to subscribe to DOM events (click, keyboard, focus) in Blazor and how to receive event arguments. They also show the `EventCallback<T>` pattern for bubbling events from child components to parents.

```razor
@@* Click events *@@
<button @@onclick="HandleClick">Click me</button>
<button @@onclick="() => count++">Increment</button>
<button @@onclick="@@(() => DeleteItem(item.Id))">Delete</button>

@@* With event args *@@
<button @@onclick="HandleClickWithArgs">Click</button>

@@code {
    private void HandleClick()
    {
        Console.WriteLine("Clicked!");
    }

    private void HandleClickWithArgs(MouseEventArgs e)
    {
        Console.WriteLine($"Clicked at {e.ClientX}, {e.ClientY}");
    }
}
```

## Common Event Types

These snippets show common event handlers (mouse, keyboard, focus, form events) and how to access event data via event argument types like `KeyboardEventArgs`.

```razor
@@* Mouse events *@@
<div @@onclick="OnClick" @@onmouseover="OnHover">...</div>

@@* Keyboard events *@@
<input @@onkeydown="OnKeyDown" @@onkeyup="OnKeyUp" />

@@* Focus events *@@
<input @@onfocus="OnFocus" @@onblur="OnBlur" />

@@* Form events *@@
<input @@oninput="OnInput" @@onchange="OnChange" />
<form @@onsubmit="OnSubmit">...</form>

@@code {
    private void OnKeyDown(KeyboardEventArgs e)
    {
        if (e.Key == "Enter") { /* Submit */ }
    }
}
```

## Preventing Default and Stopping Propagation

Use the `:preventDefault` and `:stopPropagation` modifiers to control browser default behavior and event bubbling for specific handlers.

```razor
@@* Prevent default action *@@
<a href="/other" @@onclick="HandleClick" @@onclick:preventDefault>
    Won't navigate
</a>

@@* Stop event bubbling *@@
<div @@onclick="ParentClick">
    <button @@onclick="ChildClick" @@onclick:stopPropagation>
        Only triggers ChildClick
    </button>
</div>
```

## Custom Component Events (EventCallback)

This example shows a child component exposing an `EventCallback<T>` that parents can subscribe to, useful for emitting events (like rating changes) back to the parent.

```razor
@@* RatingComponent.razor *@@
<div class="rating">
    @@for (int i = 1; i <= 5; i++)
    {
        var star = i;
        <span @@onclick="() => OnRatingChanged.InvokeAsync(star)">
            @@(star <= CurrentRating ? "★" : "☆")
        </span>
    }
</div>

@@code {
    [Parameter]
    public int CurrentRating { get; set; }

    [Parameter]
    public EventCallback<int> OnRatingChanged { get; set; }
}

@@* Parent usage *@@
<RatingComponent CurrentRating="@@rating" OnRatingChanged="HandleRating" />

@@code {
    private int rating = 3;
    private void HandleRating(int newRating) => rating = newRating;
}
```

## Async Event Handlers

Event handlers can be asynchronous (returning `Task`) so you can await I/O operations; disable UI while awaiting to prevent duplicate actions.

```razor
<button @@onclick="LoadDataAsync" disabled="@@isLoading">
    @@(isLoading ? "Loading..." : "Load Data")
</button>

@@code {
    private bool isLoading = false;
    private List<Item> items = new();

    private async Task LoadDataAsync()
    {
        isLoading = true;
        items = await Http.GetFromJsonAsync<List<Item>>("api/items") ?? new();
        isLoading = false;
    }
}
```
