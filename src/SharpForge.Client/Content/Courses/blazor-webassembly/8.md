## Basic Routing

The code below shows how to declare routes for components using the `@@page` directive, how to capture route parameters and constraints, and how to navigate programmatically using `NavigationManager`.

These two routes demonstrate multiple route templates for a single component; the router matches the first suitable template. Be careful with overlapping templates (put more specific routes first) to avoid unexpected matches.

```razor
@@page "/products"
@@page "/products/list"  @@* Multiple routes *@@

<h1>Products</h1>
```

## Route Parameters

The snippet shows how to declare a route parameter (and optional parameters) and bind it to a property on the component using `[Parameter]`.

The `{Id:int}` segment enforces that the route parameter parses as an integer and will not match strings. If parsing fails the route won't match and the request will fall through to other routes (or the NotFound page), so validate inputs or provide fallback behavior.

```razor
@@page "/products/{Id:int}"

<h1>Product @@Id</h1>

@@code {
    [Parameter]
    public int Id { get; set; }
}

@@* Optional parameter *@@
@@page "/products/{Category?}"

@@code {
    [Parameter]
    public string? Category { get; set; }
}
```

## Route Constraints

Route constraints tell the router how to parse and validate parameters. Use them to avoid invalid routes and to get strongly-typed parameters in your components.

If a constraint does not match (e.g., a non-guid string for `:guid`), the router treats it as a non-match and continues searching other routes.

```razor
@@page "/users/{Id:int}"           @@* Integer *@@
@@page "/users/{Id:guid}"          @@* GUID *@@
@@page "/orders/{Date:datetime}"   @@* DateTime *@@
@@page "/items/{Active:bool}"      @@* Boolean *@@
@@page "/search/{Query:minlength(3)}" @@* Min length *@@
```

## Query String Parameters

This example demonstrates how to read values from the query string into component parameters using `[SupplyParameterFromQuery]`.

Query values are URL-encoded; use nullable or default-valued properties to handle missing values, and remember that complex objects require manual parsing or a custom approach.

```razor
@@page "/search"

@@* URL: /search?query=blazor&page=2 *@@

@@code {
    [SupplyParameterFromQuery]
    public string? Query { get; set; }

    [SupplyParameterFromQuery]
    public int Page { get; set; } = 1;
}
```

## NavLink Component

Use `NavLink` to render navigation links that apply an "active" class when the current URL matches the link.

Set `Match` to `All` to require an exact match, or `Prefix` to match the route and its subpaths (useful for parent nav items). CSS typically styles the `active` class to indicate the current page.

```razor
@@* Adds 'active' class when route matches *@@
<NavLink href="/products" Match="NavLinkMatch.All">
    Products
</NavLink>

<NavLink href="/products" Match="NavLinkMatch.Prefix">
    Products (matches /products/*)
</NavLink>
```

## Programmatic Navigation

This shows how to inject `NavigationManager` and call `NavigateTo` for internal or external navigation (optionally forcing a full page load).

Use `forceLoad: true` to navigate to an external URL or to force a full reload; for internal SPA navigation prefer the default behavior so Blazor stays in control. You can also inspect `NavigationManager.Uri` to read the current URL.

```razor
@@inject NavigationManager Navigation

<button @@onclick="GoToProducts">View Products</button>

@@code {
    private void GoToProducts()
    {
        Navigation.NavigateTo("/products");
    }

    private void GoToProduct(int id)
    {
        Navigation.NavigateTo($"/products/{id}");
    }

    private void GoExternal()
    {
        Navigation.NavigateTo("https://google.com", forceLoad: true);
    }
}
```

## Not Found Page

This snippet shows how to configure a NotFound view in `App.razor`, returning a friendly 404 message for unmatched routes.

Use `NotFound` to display custom messaging or redirect users back to a safe page; it's rendered when no route matches.

```razor
@@* In App.razor *@@
<Router AppAssembly="@@typeof(App).Assembly">
    <Found Context="routeData">
        <RouteView RouteData="@@routeData" DefaultLayout="@@typeof(MainLayout)" />
    </Found>
    <NotFound>
        <LayoutView Layout="@@typeof(MainLayout)">
            <h1>404 - Page Not Found</h1>
            <p>Sorry, the page you requested doesn't exist.</p>
            <a href="/">Go Home</a>
        </LayoutView>
    </NotFound>
</Router>
```
