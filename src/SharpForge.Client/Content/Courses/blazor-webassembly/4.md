## Basic Parameters

This snippet demonstrates declaring component inputs using `[Parameter]` and how values are passed into a component from its parent. It also shows default values and how to use the values in markup.

```razor
@@* Alert.razor *@@
<div class="alert alert-@@Type">
    @@Message
</div>

@@code {
    [Parameter]
    public string Message { get; set; } = "";

    [Parameter]
    public string Type { get; set; } = "info";
}

@@* Usage *@@
<Alert Message="Operation successful!" Type="success" />
<Alert Message="Something went wrong" Type="danger" />
```

## Required Parameters

This snippet shows how to mark required component parameters so editors and tooling surface missing values as warnings.

```csharp
@@code {
    [Parameter, EditorRequired]
    public string Title { get; set; } = default!;

    [Parameter]
    public string? Subtitle { get; set; }
}
```

## Child Content (RenderFragment)

Use `RenderFragment` to allow callers to pass a chunk of UI (child content) into your component; this example shows a Card component that renders any nested content.

```razor
@@* Card.razor *@@
<div class="card">
    <div class="card-header">@@Title</div>
    <div class="card-body">
        @@ChildContent
    </div>
</div>

@@code {
    [Parameter]
    public string Title { get; set; } = "";

    [Parameter]
    public RenderFragment? ChildContent { get; set; }
}

@@* Usage *@@
<Card Title="Welcome">
    <p>This content goes inside the card!</p>
    <button>Click me</button>
</Card>
```

## Cascading Parameters

This example demonstrates providing a value to a subtree via `CascadingValue` and receiving it with `[CascadingParameter]` in descendant components.

```razor
@@* Parent provides the value *@@
<CascadingValue Value="@@theme">
    <ChildComponent />
    <AnotherChild />
</CascadingValue>

@@code {
    private Theme theme = new Theme { Primary = "#007bff" };
}

@@* Any descendant can receive it *@@
@@code {
    [CascadingParameter]
    public Theme? Theme { get; set; }
}
```

## Attribute Splatting

Attribute splatting lets callers pass arbitrary HTML attributes to the rendered element; use `CaptureUnmatchedValues=true` on a dictionary parameter to collect them.

```razor
@@* CustomButton.razor *@@
<button @@attributes="AdditionalAttributes" class="btn @@Class">
    @@ChildContent
</button>

@@code {
    [Parameter]
    public string Class { get; set; } = "btn-primary";

    [Parameter]
    public RenderFragment? ChildContent { get; set; }

    [Parameter(CaptureUnmatchedValues = true)]
    public Dictionary<string, object>? AdditionalAttributes { get; set; }
}

@@* Usage - extra attributes passed through *@@
<CustomButton id="submit-btn" data-testid="submit">Submit</CustomButton>
```
