## Publishing Your Application
Publishing prepares your application for deployment. .NET offers several publishing options depending on your needs—from simple deployments to optimized single-file executables.
## Framework-Dependent vs Self-Contained
<div class="comparison-grid">
<div class="comparison-card">
#### Framework-Dependent
Requires .NET runtime to be installed on the target machine.
- ✅ Smaller file size
- ✅ Shares runtime with other apps
- ❌ Runtime must be pre-installed
<code>dotnet publish</code>
</div>
<div class="comparison-card">
#### Self-Contained
Includes the .NET runtime with your app.
- ✅ No runtime installation needed
- ✅ Control exact runtime version
- ❌ Larger file size (~60-80MB)
<code>dotnet publish --self-contained</code>
</div>
</div>
## Basic Publishing
```bash
# Framework-dependent (requires runtime on target)
dotnet publish -c Release

# Self-contained (includes runtime)
dotnet publish -c Release --self-contained

# Output is in bin/Release/net8.0/publish/```
## Publishing for Specific Platforms
Use Runtime Identifiers (RIDs) to target specific platforms:
```bash
# Windows x64
dotnet publish -c Release -r win-x64 --self-contained

# Windows ARM64
dotnet publish -c Release -r win-arm64 --self-contained

# Linux x64
dotnet publish -c Release -r linux-x64 --self-contained

# macOS Apple Silicon
dotnet publish -c Release -r osx-arm64 --self-contained

# macOS Intel
dotnet publish -c Release -r osx-x64 --self-contained```

## Single File Deployment
Bundle everything into a single executable:
```bash
# Single file, self-contained
dotnet publish -c Release -r win-x64 --self-contained \
    -p:PublishSingleFile=true

# Even smaller with trimming
dotnet publish -c Release -r win-x64 --self-contained \
    -p:PublishSingleFile=true \
    -p:PublishTrimmed=true```
Or configure in the project file:
```xml
<PropertyGroup>
  <PublishSingleFile>true</PublishSingleFile>
  <SelfContained>true</SelfContained>
  <RuntimeIdentifier>win-x64</RuntimeIdentifier>
  <PublishTrimmed>true</PublishTrimmed>
</PropertyGroup>```
## ReadyToRun (R2R) Compilation
Pre-compile to native code for faster startup:
```bash
dotnet publish -c Release -r win-x64 --self-contained \
    -p:PublishReadyToRun=true```
This increases file size but reduces JIT compilation at startup.
## Native AOT Compilation
.NET 8+ supports Ahead-of-Time compilation to native code:
```xml
<PropertyGroup>
  <PublishAot>true</PublishAot>
</PropertyGroup>```
```bash
dotnet publish -c Release -r win-x64```
Benefits:
- Fastest startup time
- Smallest memory footprint
- No JIT compilation
<div class="warning-box">
<div class="warning-box-header">
<span>⚠️ Limitations</span>
</div>
Native AOT doesn't support all .NET features (like runtime code generation). Test thoroughly before using in production.
</div>
## Docker Deployment
Containerize your .NET application:
```dockerfile
# Dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy and restore
COPY *.csproj ./
RUN dotnet restore

# Copy and build
COPY . ./
RUN dotnet publish -c Release -o /app/publish

# Runtime image
FROM mcr.microsoft.com/dotnet/aspnet:8.0
WORKDIR /app
COPY --from=build /app/publish .
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApp.dll"]```
```bash
# Build the image
docker build -t myapp .

# Run the container
docker run -p 8080:8080 myapp```
## Deploying to Azure
### Azure App Service
```bash
# Login to Azure
az login

# Create resource group
az group create --name myResourceGroup --location eastus

# Create App Service plan
az appservice plan create --name myPlan --resource-group myResourceGroup --sku B1

# Create web app
az webapp create --name myapp --resource-group myResourceGroup --plan myPlan

# Deploy
dotnet publish -c Release -o ./publish
cd publish
zip -r ../deploy.zip .
az webapp deploy --resource-group myResourceGroup --name myapp --src-path ../deploy.zip```
### Using Visual Studio / VS Code
Right-click the project and select "Publish" to use the GUI-based deployment wizard.
## Deploying to Linux
For a Linux server:
```bash
# Publish for Linux
dotnet publish -c Release -r linux-x64 --self-contained -o ./publish

# Copy to server
scp -r ./publish/* user@server:/var/www/myapp/

# On the server, create a systemd service
sudo nano /etc/systemd/system/myapp.service```
```ini
[Unit]
Description=My .NET App

[Service]
WorkingDirectory=/var/www/myapp
ExecStart=/var/www/myapp/MyApp
Restart=always
RestartSec=10
User=www-data
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=DOTNET_PRINT_TELEMETRY_MESSAGE=false

[Install]
WantedBy=multi-user.target```
```bash
# Enable and start
sudo systemctl enable myapp
sudo systemctl start myapp
sudo systemctl status myapp```
## Publishing Best Practices
- <strong>Always use Release configuration</strong> for production
- <strong>Use self-contained</strong> when you can't control the target environment
- <strong>Enable trimming</strong> for smaller deployments (test thoroughly)
- <strong>Use Docker</strong> for consistent deployments across environments
- <strong>Set environment variables</strong> for configuration (not appsettings.json)
- <strong>Never deploy debug builds</strong> to production
