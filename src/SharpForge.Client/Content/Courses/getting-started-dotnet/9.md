## Debugging in .NET
Debugging is an essential skill for any developer. .NET provides excellent debugging support in Visual Studio, VS Code, and JetBrains Rider. In this lesson, we'll cover the tools and techniques you need to find and fix bugs efficiently.
## Setting Breakpoints
Breakpoints pause execution so you can inspect the state of your application:
<div class="debug-tips">
<div class="tip">
#### Regular Breakpoints
Click in the left margin or press F9 to set/remove a breakpoint on a line.
</div>
<div class="tip">
#### Conditional Breakpoints
Right-click a breakpoint to add conditions. Only break when <code>i > 100</code>.
</div>
<div class="tip">
#### Logpoints
Log a message instead of breaking. Great for production-like debugging.
</div>
</div>
```csharp
// Add a conditional breakpoint here that only breaks when count > 10
for (int i = 0; i < 100; i++)
{
    var count = Process(i); // Set breakpoint on this line
    Console.WriteLine(count);
}```

Once paused at a breakpoint, use these controls:

</div>

</div>
<div class="control-item">

</div>
</div>
## Inspecting Variables
While debugging, you can inspect variable values:
- <strong>Hover:</strong> Mouse over a variable to see its value
- <strong>Locals Window:</strong> Shows all local variables in current scope
- <strong>Watch Window:</strong> Add specific expressions to monitor
- <strong>Immediate Window:</strong> Execute code and evaluate expressions
```csharp
// In the Immediate Window, you can:
// - Evaluate expressions: user.Name
// - Call methods: user.GetFullName()
// - Change values: user.Age = 30
// - Check conditions: user.Age > 18```
## Debugging in VS Code
VS Code requires a <code>launch.json</code> configuration:
```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": ".NET Core Launch (console)",
      "type": "coreclr",
      "request": "launch",
      "preLaunchTask": "build",
      "program": "${workspaceFolder}/bin/Debug/net8.0/MyApp.dll",
      "args": [],
      "cwd": "${workspaceFolder}",
      "console": "integratedTerminal",
      "stopAtEntry": false
    }
  ]
}```
Press F5 or use the Run and Debug panel to start debugging.
## Logging
Strategic logging helps you understand what your application is doing:
```csharp
using Microsoft.Extensions.Logging;

public class UserService
{
    private readonly ILogger<UserService> _logger;

    public UserService(ILogger<UserService> logger)
    {
        _logger = logger;
    }

    public async Task<User?> GetUserAsync(int id)
    {
        _logger.LogDebug("Getting user with ID: {UserId}", id);

        try
        {
            var user = await _repository.FindAsync(id);

            if (user == null)
            {
_logger.LogWarning("User not found: {UserId}", id);
return null;
            }

            _logger.LogInformation("Found user: {UserName}", user.Name);
            return user;
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Error getting user {UserId}", id);
            throw;
        }
    }
}```

## Common Exceptions
Learn to recognize and fix these common exceptions:
<div class="exception-grid">
<div class="exception-card">
#### NullReferenceException
You tried to use a null object reference.
```csharp
// Fix: Check for null
if (user != null)
{
    Console.WriteLine(user.Name);
}
// Or use null-conditional
Console.WriteLine(user?.Name);```
</div>
<div class="exception-card">
#### ArgumentNullException
A null argument was passed to a method that doesn't accept it.
```csharp
// Fix: Validate arguments
public void Process(string data)
{
    ArgumentNullException.ThrowIfNull(data);
    // ... process data
}```
</div>
<div class="exception-card">
#### InvalidOperationException
The object is in an invalid state for the operation.
```csharp
// Common: Empty collection
var first = list.First(); // Throws if empty
var first = list.FirstOrDefault(); // Returns null/default```
</div>
</div>
## Using Debug.Assert
Assertions help catch programming errors during development:
```csharp
using System.Diagnostics;

public void ProcessOrder(Order order)
{
    // These only run in Debug builds
    Debug.Assert(order != null, "Order cannot be null");
    Debug.Assert(order.Items.Count > 0, "Order must have items");
    Debug.Assert(order.Total >= 0, "Total cannot be negative");

    // Process the order...
}```
## Analyzing Stack Traces
Stack traces show you exactly where an exception occurred:
```bash
Unhandled exception. System.NullReferenceException: Object reference not set
   at MyApp.Services.UserService.GetUser(Int32 id) in UserService.cs:line 25
   at MyApp.Controllers.UsersController.Get(Int32 id) in UsersController.cs:line 18
   at Program.Main(String[] args) in Program.cs:line 10```
Read from bottom to top to understand the call chain. The top line shows where the error occurred.
## Diagnostic Tools
### dotnet-counters
```bash
# Install
dotnet tool install --global dotnet-counters

# Monitor your app
dotnet-counters monitor --process-id 12345```
### dotnet-trace
```bash
# Collect a trace
dotnet tool install --global dotnet-trace
dotnet-trace collect --process-id 12345```
### dotnet-dump
```bash
# Capture a memory dump
dotnet tool install --global dotnet-dump
dotnet-dump collect --process-id 12345```
