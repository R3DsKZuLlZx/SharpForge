## The Power of the Command Line
The .NET CLI (Command Line Interface) is a cross-platform tool for developing, building, running, and publishing .NET applications. It's the foundation of .NET development—even IDEs like Visual Studio use the CLI under the hood.
Mastering the CLI will make you more productive and give you a deeper understanding of how .NET works.
## Basic CLI Structure
All .NET CLI commands follow this pattern:
```bash
dotnet [command] [arguments] [options]```
For example:
```bash
# Create a new console application
dotnet new console --name MyApp

# Build the current project
dotnet build

# Run the application
dotnet run```
## Creating Projects with 'dotnet new'
The <code>dotnet new</code> command creates new projects and files from templates:
```bash
# See all available templates
dotnet new list

# Create a console application
dotnet new console -n MyConsoleApp

# Create a web API
dotnet new webapi -n MyApi

# Create a Blazor WebAssembly app
dotnet new blazorwasm -n MyBlazorApp

# Create a class library
dotnet new classlib -n MyLibrary

# Create a solution file
dotnet new sln -n MySolution```

## Building Projects
The <code>dotnet build</code> command compiles your project:
```bash
# Build the project in the current directory
dotnet build

# Build in Release mode
dotnet build -c Release

# Build a specific project
dotnet build MyProject.csproj

# Build with verbose output
dotnet build -v detailed```

## Running Applications
Use <code>dotnet run</code> to build and execute your application:
```bash
# Build and run the current project
dotnet run

# Run in Release mode
dotnet run -c Release

# Pass arguments to your application
dotnet run -- arg1 arg2

# Run a specific project
dotnet run --project ./src/MyApp/MyApp.csproj

# Run without building (use existing build)
dotnet run --no-build```
### Hot Reload with 'dotnet watch'
During development, use <code>dotnet watch</code> to automatically restart your app when files change:
```bash
# Run with hot reload
dotnet watch run

# Run tests with watch
dotnet watch test```
## Managing Dependencies
Add, remove, and list NuGet package references:
```bash
# Add a NuGet package
dotnet add package Newtonsoft.Json

# Add a specific version
dotnet add package Serilog --version 3.0.0

# Remove a package
dotnet remove package Newtonsoft.Json

# List all packages
dotnet list package

# Check for outdated packages
dotnet list package --outdated```
### Project References
```bash
# Add a reference to another project
dotnet add reference ../MyLibrary/MyLibrary.csproj

# Remove a project reference
dotnet remove reference ../MyLibrary/MyLibrary.csproj

# List project references
dotnet list reference```
## Working with Solutions
Solutions group multiple projects together:
```bash
# Create a new solution
dotnet new sln -n MySolution

# Add projects to the solution
dotnet sln add ./src/MyApp/MyApp.csproj
dotnet sln add ./src/MyLibrary/MyLibrary.csproj
dotnet sln add ./tests/MyApp.Tests/MyApp.Tests.csproj

# List projects in the solution
dotnet sln list

# Remove a project from the solution
dotnet sln remove ./src/OldProject/OldProject.csproj

# Build the entire solution
dotnet build MySolution.sln```
## Running Tests
Execute unit tests with the <code>dotnet test</code> command:
```bash
# Run all tests
dotnet test

# Run with detailed output
dotnet test -v normal

# Run specific tests by name
dotnet test --filter "ClassName=MyTests"

# Generate code coverage
dotnet test --collect:"XPlat Code Coverage"

# Run tests in parallel
dotnet test --parallel```
## Publishing Applications
The <code>dotnet publish</code> command prepares your app for deployment:
```bash
# Publish for the current platform
dotnet publish -c Release

# Publish as self-contained (includes runtime)
dotnet publish -c Release --self-contained

# Publish for a specific platform
dotnet publish -c Release -r win-x64
dotnet publish -c Release -r linux-x64
dotnet publish -c Release -r osx-arm64

# Publish as single file
dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true```
