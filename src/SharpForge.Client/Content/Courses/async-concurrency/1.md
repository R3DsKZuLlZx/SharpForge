## Why Asynchronous Programming?

Asynchronous programming allows your application to remain responsive while waiting for I/O operations like network requests, file access, or database queries.

## Synchronous vs Asynchronous

The examples below contrast blocking synchronous calls with non-blocking async methods - prefer the async pattern to avoid thread starvation and keep applications responsive.

```csharp
// Synchronous - blocks the thread while waiting
public string GetData()
{
    var data = httpClient.GetStringAsync(url).Result;  // Thread blocked!
    return data;
}

// Asynchronous - frees the thread while waiting
public async Task<string> GetDataAsync()
{
    var data = await httpClient.GetStringAsync(url);  // Thread free to do other work
    return data;
}
```

## The Thread Pool

This snippet demonstrates how awaiting returns the thread to the pool and that continuations may run on a different thread, don't rely on thread affinity unless you capture a synchronization context.

```csharp
// When you await, the thread returns to the pool
// When the operation completes, a thread continues execution
public async Task ProcessAsync()
{
    Console.WriteLine($"Before: Thread {Thread.CurrentThread.ManagedThreadId}");
    
    await Task.Delay(100);  // Thread returned to pool during delay
    
    Console.WriteLine($"After: Thread {Thread.CurrentThread.ManagedThreadId}");
    // May be a different thread!
}
```
