## Why ValueTask?

Task is a reference type so every async call allocates. ValueTask is a struct that can avoid allocations when the result is available synchronously.

## When to Use ValueTask

Example showing a method that often completes synchronously (cache hit) and sometimes asynchronously; returning `ValueTask<T>` avoids allocations on the fast path.

```csharp
// Perfect for methods that often complete synchronously
public class Cache
{
    private readonly Dictionary<string, Data> _cache = new();

    // Often returns cached value (sync), sometimes fetches (async)
    public async ValueTask<Data> GetAsync(string key)
    {
        if (_cache.TryGetValue(key, out var cached))
            return cached;  // No allocation!

        var data = await FetchFromDatabaseAsync(key);
        _cache[key] = data;
        return data;
    }
}
```

## ValueTask Rules

Demonstrates incorrect and correct usage patterns for `ValueTask` - don't await it multiple times; convert to `Task` if you need multiple awaits.

<div class="warning-box">
    <div class="warning-box-header"><span>⚠️ Important Rules</span></div>
    <ul>
        <li>Never await a ValueTask more than once</li>
        <li>Never use .Result or .GetAwaiter().GetResult() before completion</li>
        <li>If you need multiple awaits, convert to Task first</li>
    </ul>
</div>

```csharp
// ❌ WRONG - awaiting twice
var valueTask = GetAsync(key);
var result1 = await valueTask;
var result2 = await valueTask;  // Undefined behavior!

// ✅ CORRECT - convert to Task if needed
var task = GetAsync(key).AsTask();
var result1 = await task;
var result2 = await task;  // Safe
```
