## AsParallel()

Turn a LINQ query into a parallel one with `AsParallel()` for CPU-bound operations; keep in mind PLINQ parallelizes the query pipeline across threads.

```csharp
// Sequential LINQ
var results = numbers
    .Where(n => n % 2 == 0)
    .Select(n => ExpensiveCalculation(n))
    .ToList();

// Parallel LINQ - just add AsParallel()!
var results = numbers
    .AsParallel()
    .Where(n => n % 2 == 0)
    .Select(n => ExpensiveCalculation(n))
    .ToList();
```

## Controlling Parallelism

Use `WithDegreeOfParallelism` to limit threads and `WithCancellation` to support cancellation in PLINQ queries.

```csharp
var results = data
    .AsParallel()
    .WithDegreeOfParallelism(4)  // Max 4 threads
    .WithCancellation(cancellationToken)
    .WithExecutionMode(ParallelExecutionMode.ForceParallelism)
    .Select(x => Process(x))
    .ToList();
```

## Preserving Order

By default PLINQ may return results out of order for speed; use `AsOrdered()` if you need to preserve original sequence at cost of some performance.

```csharp
// Order NOT preserved by default (faster)
var unordered = data.AsParallel().Select(Process).ToList();

// Preserve order (slower)
var ordered = data
    .AsParallel()
    .AsOrdered()  // Maintain input order
    .Select(Process)
    .ToList();
```

## ForAll for Side Effects

Use `ForAll` to perform side-effecting actions in parallel without materializing a collection; don't rely on ordering with ForAll.

```csharp
// Don't use ToList() just for side effects
data
    .AsParallel()
    .Where(x => x.IsActive)
    .ForAll(x =>
    {
        // Process each in parallel (no results returned)
        ProcessItem(x);
    });
```
