## The async Modifier

Mark methods `async` to enable `await`; prefer returning `Task` or `Task<T>` (avoid async void except for event handlers).

```csharp
// async enables the await keyword in the method
public async Task<string> GetDataAsync()
{
    // Can use await here
    var data = await httpClient.GetStringAsync(url);
    return data;
}

// Return types for async methods:
// - Task         (void equivalent)
// - Task<T>      (returns T)
// - ValueTask    (optimization)
// - ValueTask<T> (optimization with return)
// - async void   (AVOID - only for event handlers)
```

## The await Keyword

`await` checks for completion and either continues synchronously or registers a continuation - it's the key primitive for composing asynchronous operations.

```csharp
public async Task ProcessAsync()
{
    // await does three things:
    // 1. Checks if task is complete - if yes, continues synchronously
    // 2. If not complete, registers continuation and returns
    // 3. When task completes, resumes execution

    var result = await GetDataAsync();  // Execution pauses here
    
    // This code runs after GetDataAsync completes
    Console.WriteLine(result);
}
```

## Multiple Awaits

Start independent tasks before awaiting them to run them concurrently; sequential awaits wait for each task before starting the next.

```csharp
// Sequential - one after another
public async Task SequentialAsync()
{
    var user = await GetUserAsync();      // Wait for this
    var orders = await GetOrdersAsync();  // Then wait for this
    // Total time = GetUser + GetOrders
}

// Concurrent - start both, await both
public async Task ConcurrentAsync()
{
    var userTask = GetUserAsync();        // Start this
    var ordersTask = GetOrdersAsync();    // Start this immediately
    
    var user = await userTask;            // Wait for first
    var orders = await ordersTask;        // Wait for second
    // Total time = Max(GetUser, GetOrders)
}
```

## ConfigureAwait

Use `ConfigureAwait(false)` in library code to avoid capturing synchronization context, improving performance and avoiding deadlocks in some hosting models.

```csharp
// In library code, use ConfigureAwait(false)
public async Task<string> GetDataAsync()
{
    // Don't capture synchronization context
    var data = await httpClient.GetStringAsync(url)
        .ConfigureAwait(false);
    
    return data;
}

// In UI/ASP.NET code, usually omit (defaults to true)
public async Task ButtonClickAsync()
{
    var data = await GetDataAsync();  // Returns to UI thread
    label.Text = data;  // Safe to update UI
}
```
