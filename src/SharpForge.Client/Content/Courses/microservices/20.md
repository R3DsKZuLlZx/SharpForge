## Externalizing Configuration

Microservices need configuration: connection strings, feature flags, API URLs. Hardcoding these values in images makes them inflexible. Kubernetes provides **ConfigMaps** for general configuration and **Secrets** for sensitive data.

## ConfigMaps

### Creating a ConfigMap

```yaml
# k8s/order-service/configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: order-service-config
  namespace: microservices
data:
  ASPNETCORE_ENVIRONMENT: "Production"
  Logging__LogLevel__Default: "Information"
  ServiceUrls__Inventory: "http://inventory-service"
  ServiceUrls__Payment: "http://payment-service"
```

Or create from the command line:

```bash
# From literal values
kubectl create configmap order-service-config \
    --from-literal=ASPNETCORE_ENVIRONMENT=Production \
    --from-literal=ServiceUrls__Inventory=http://inventory-service \
    -n microservices

# From a file
kubectl create configmap order-service-appsettings \
    --from-file=appsettings.Production.json \
    -n microservices
```

### Using ConfigMaps as Environment Variables

```yaml
spec:
  containers:
    - name: order-service
      image: order-service:1.0.0
      envFrom:
        - configMapRef:
            name: order-service-config
```

Or map specific keys:

```yaml
spec:
  containers:
    - name: order-service
      env:
        - name: ASPNETCORE_ENVIRONMENT
          valueFrom:
            configMapKeyRef:
              name: order-service-config
              key: ASPNETCORE_ENVIRONMENT
```

### Mounting ConfigMaps as Files

```yaml
spec:
  containers:
    - name: order-service
      volumeMounts:
        - name: config-volume
          mountPath: /app/config
          readOnly: true
  volumes:
    - name: config-volume
      configMap:
        name: order-service-appsettings
```

## Secrets

### Creating Secrets

```yaml
# k8s/order-service/secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: order-service-secrets
  namespace: microservices
type: Opaque
data:
  ConnectionStrings__OrderDb: U2VydmVyPW9yZGVyLWRiO0RhdGFiYXNlPW9yZGVycztVc2VyPXNhO1Bhc3N3b3JkPVlvdXJQYXNzMTIzIQ==
  RabbitMQ__Password: Z3Vlc3Q=
```

<div class="warning-box">
    <div class="warning-box-header"><span>⚠️ Important</span></div>
    <p>Kubernetes Secrets are only <strong>base64-encoded</strong>, not encrypted. Anyone with access to the namespace can decode them. For production, use an external secret manager.</p>
</div>

Or create from the command line (handles encoding):

```bash
kubectl create secret generic order-service-secrets \
    --from-literal=ConnectionStrings__OrderDb="Server=order-db;Database=orders;..." \
    --from-literal=RabbitMQ__Password="guest" \
    -n microservices
```

### Using Secrets as Environment Variables

```yaml
spec:
  containers:
    - name: order-service
      envFrom:
        - secretRef:
            name: order-service-secrets
      envFrom:
        - configMapRef:
            name: order-service-config
```

## .NET Configuration Integration

.NET reads environment variables automatically, so ConfigMap and Secret values are available through `IConfiguration`:

```csharp
var builder = WebApplication.CreateBuilder(args);

// These values come from ConfigMaps and Secrets via environment variables
var connectionString = builder.Configuration.GetConnectionString("OrderDb");
var inventoryUrl = builder.Configuration["ServiceUrls:Inventory"];

builder.Services.AddDbContext<OrderDbContext>(options =>
    options.UseSqlServer(connectionString));

builder.Services.AddHttpClient<InventoryClient>(client =>
    client.BaseAddress = new Uri(inventoryUrl!));
```

## External Secret Managers

For production, integrate with a dedicated secret manager:

```bash
# Azure Key Vault with the Secrets Store CSI Driver
helm install csi-secrets-store secrets-store-csi-driver/secrets-store-csi-driver \
    --namespace kube-system
```

```yaml
# SecretProviderClass for Azure Key Vault
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: azure-kv-provider
spec:
  provider: azure
  parameters:
    keyvaultName: "my-keyvault"
    objects: |
      array:
        - |
          objectName: order-db-connection-string
          objectType: secret
    tenantId: "your-tenant-id"
```

## Best Practices

- Use **ConfigMaps** for non-sensitive settings, **Secrets** for credentials
- **Don't commit Secrets** to source control — use CI/CD to create them
- Use **external secret managers** (Key Vault, Secrets Manager) for production
- Mount secrets as **environment variables** for simple key-value pairs, as **files** for certificates or complex config
- Use the `.NET configuration system` — it reads environment variables with no extra code
- **Rotate secrets** regularly and plan for zero-downtime rotation
