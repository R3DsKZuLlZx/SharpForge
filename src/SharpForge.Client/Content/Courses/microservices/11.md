## Storing State as Events

Traditional systems store the **current state** in a database. Event sourcing takes a different approach: it stores every **state change** as an immutable event. The current state is derived by replaying those events.

## Defining Events

Events describe what happened in the past — they're immutable facts:

```csharp
public abstract record OrderEvent(Guid OrderId, DateTime OccurredAt);

public record OrderCreated(
    Guid OrderId, Guid CustomerId, DateTime OccurredAt)
    : OrderEvent(OrderId, OccurredAt);

public record OrderItemAdded(
    Guid OrderId, int ProductId, string ProductName,
    int Quantity, decimal UnitPrice, DateTime OccurredAt)
    : OrderEvent(OrderId, OccurredAt);

public record OrderPlaced(
    Guid OrderId, decimal TotalAmount, DateTime OccurredAt)
    : OrderEvent(OrderId, OccurredAt);

public record OrderCancelled(
    Guid OrderId, string Reason, DateTime OccurredAt)
    : OrderEvent(OrderId, OccurredAt);
```

## The Aggregate with Event Sourcing

The aggregate applies events to update its state and records new events for uncommitted changes:

```csharp
public class Order
{
    public Guid Id { get; private set; }
    public Guid CustomerId { get; private set; }
    public OrderStatus Status { get; private set; }
    private readonly List<OrderItem> _items = [];
    public IReadOnlyList<OrderItem> Items => _items.AsReadOnly();
    public decimal Total => _items.Sum(i => i.Quantity * i.UnitPrice);

    // Uncommitted events
    private readonly List<OrderEvent> _changes = [];
    public IReadOnlyList<OrderEvent> GetUncommittedChanges() => _changes.AsReadOnly();
    public void ClearChanges() => _changes.Clear();

    // Create a new order
    public static Order Create(Guid customerId)
    {
        var order = new Order();
        order.Apply(new OrderCreated(Guid.NewGuid(), customerId, DateTime.UtcNow));
        return order;
    }

    public void AddItem(int productId, string productName, int quantity, decimal unitPrice)
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException("Cannot add items to a placed order.");
        Apply(new OrderItemAdded(Id, productId, productName, quantity, unitPrice, DateTime.UtcNow));
    }

    public void Place()
    {
        if (_items.Count == 0)
            throw new InvalidOperationException("Cannot place an empty order.");
        Apply(new OrderPlaced(Id, Total, DateTime.UtcNow));
    }

    // Apply dispatches to the correct When method and records the event
    private void Apply(OrderEvent @event)
    {
        When(@event);
        _changes.Add(@event);
    }

    // Rebuild state from a stored event (no recording)
    public void Replay(OrderEvent @event) => When(@event);

    private void When(OrderEvent @event)
    {
        switch (@event)
        {
            case OrderCreated e:
                Id = e.OrderId;
                CustomerId = e.CustomerId;
                Status = OrderStatus.Draft;
                break;
            case OrderItemAdded e:
                _items.Add(new OrderItem(e.ProductId, e.ProductName, e.Quantity, e.UnitPrice));
                break;
            case OrderPlaced:
                Status = OrderStatus.Placed;
                break;
            case OrderCancelled:
                Status = OrderStatus.Cancelled;
                break;
        }
    }
}
```

## The Event Store

An event store persists events in order. Here's a simplified interface:

```csharp
public interface IEventStore
{
    Task AppendAsync(Guid streamId, IEnumerable<object> events, int expectedVersion, CancellationToken ct);
    Task<List<object>> GetEventsAsync(Guid streamId, CancellationToken ct);
}
```

Load an aggregate by replaying its events:

```csharp
public class OrderRepository
{
    private readonly IEventStore _store;

    public OrderRepository(IEventStore store) => _store = store;

    public async Task<Order> GetAsync(Guid orderId, CancellationToken ct)
    {
        var events = await _store.GetEventsAsync(orderId, ct);
        var order = new Order();
        foreach (var @event in events.Cast<OrderEvent>())
            order.Replay(@event);
        return order;
    }

    public async Task SaveAsync(Order order, int expectedVersion, CancellationToken ct)
    {
        await _store.AppendAsync(order.Id, order.GetUncommittedChanges(), expectedVersion, ct);
        order.ClearChanges();
    }
}
```

## Projections

Event-sourced aggregates are optimized for writes. For reads, build **projections** — read-optimized views materialized from the event stream:

```csharp
public class OrderSummaryProjection
{
    public Guid OrderId { get; set; }
    public Guid CustomerId { get; set; }
    public string Status { get; set; } = "";
    public int ItemCount { get; set; }
    public decimal TotalAmount { get; set; }
    public DateTime LastUpdated { get; set; }
}

public class OrderSummaryProjector
{
    private readonly IProjectionStore _store;

    public async Task HandleAsync(OrderEvent @event)
    {
        switch (@event)
        {
            case OrderCreated e:
                await _store.CreateAsync(new OrderSummaryProjection
                {
                    OrderId = e.OrderId, CustomerId = e.CustomerId,
                    Status = "Draft", LastUpdated = e.OccurredAt
                });
                break;
            case OrderItemAdded e:
                var summary = await _store.GetAsync(e.OrderId);
                summary.ItemCount++;
                summary.TotalAmount += e.Quantity * e.UnitPrice;
                summary.LastUpdated = e.OccurredAt;
                await _store.UpdateAsync(summary);
                break;
            case OrderPlaced e:
                var placed = await _store.GetAsync(e.OrderId);
                placed.Status = "Placed";
                placed.LastUpdated = e.OccurredAt;
                await _store.UpdateAsync(placed);
                break;
        }
    }
}
```

## Best Practices

- **Events are immutable** — never update or delete them. Add compensating events instead.
- **Use snapshots** for aggregates with many events to avoid slow replays.
- **Projections are disposable** — you can always rebuild them from the event stream.
- **Version your events** — add fields carefully and handle missing fields in old events.
- Event sourcing adds complexity — **use it where the audit trail and history genuinely add value** (orders, financial transactions, compliance).
