## From Docker Compose to Kubernetes

You've been running services locally with Docker Compose. Now it's time to deploy to Kubernetes. This lesson walks through organizing manifests, deploying a multi-service system, and setting up a basic CI/CD flow.

## Manifest Organization

Structure your manifests per service:

```bash
k8s/
├── namespace.yaml
├── order-service/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
├── inventory-service/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
└── rabbitmq/
    ├── deployment.yaml
    └── service.yaml
```

## Complete Service Deployment

### Namespace

```yaml
# k8s/namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: microservices
```

### Order Service

```yaml
# k8s/order-service/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  namespace: microservices
spec:
  replicas: 2
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
    spec:
      containers:
        - name: order-service
          image: myregistry.azurecr.io/order-service:1.0.0
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: order-service-config
          resources:
            requests:
              memory: "128Mi"
              cpu: "100m"
            limits:
              memory: "256Mi"
              cpu: "500m"
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10
          livenessProbe:
            httpGet:
              path: /health/live
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 30
```

```yaml
# k8s/order-service/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: order-service
  namespace: microservices
spec:
  selector:
    app: order-service
  ports:
    - port: 80
      targetPort: 8080
```

## Health Endpoints in .NET

Configure separate readiness and liveness probes:

```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(
        builder.Configuration.GetConnectionString("OrderDb")!,
        name: "database",
        tags: ["ready"])
    .AddRabbitMQ(
        builder.Configuration.GetConnectionString("RabbitMQ")!,
        name: "rabbitmq",
        tags: ["ready"]);

var app = builder.Build();

// Liveness — is the process alive?
app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false  // No dependency checks
});

// Readiness — can it handle traffic?
app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready")
});
```

## Deploying Everything

```bash
# Apply all manifests
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/order-service/
kubectl apply -f k8s/inventory-service/
kubectl apply -f k8s/rabbitmq/

# Verify
kubectl get all -n microservices

# Watch pods come up
kubectl get pods -n microservices -w
```

## Using Kustomize

Kustomize lets you manage base manifests with environment-specific overlays:

```bash
k8s/
├── base/
│   ├── kustomization.yaml
│   ├── order-service/
│   │   ├── deployment.yaml
│   │   └── service.yaml
│   └── inventory-service/
│       ├── deployment.yaml
│       └── service.yaml
└── overlays/
    ├── dev/
    │   └── kustomization.yaml
    └── prod/
        └── kustomization.yaml
```

```yaml
# k8s/overlays/prod/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
patchesStrategicMerge:
  - increase-replicas.yaml
namespace: microservices-prod
```

```bash
# Apply production overlay
kubectl apply -k k8s/overlays/prod
```

## CI/CD Pipeline

A basic GitHub Actions pipeline for building and deploying:

```yaml
# .github/workflows/deploy.yml
name: Build and Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build and push image
        run: |
          docker build -t myregistry.azurecr.io/order-service:${{ github.sha }} \
            -f OrderService/Dockerfile .
          docker push myregistry.azurecr.io/order-service:${{ github.sha }}

      - name: Update deployment image
        run: |
          kubectl set image deployment/order-service \
            order-service=myregistry.azurecr.io/order-service:${{ github.sha }} \
            -n microservices
```

## Best Practices

- Always define **readiness and liveness probes** — Kubernetes can't manage what it can't observe
- Use **Kustomize or Helm** for managing environment-specific differences
- Tag images with **commit SHA or semver** — never use `latest` in production
- Set **resource requests and limits** on every container
- Use a **container registry** (ACR, ECR, GCR) — don't build images on the cluster
- Test manifests locally with `kubectl apply --dry-run=client -f file.yaml`
