## Container Orchestration

Docker Compose works for local development, but production needs more: automatic restarts, scaling, rolling deployments, and service discovery across multiple machines. **Kubernetes (K8s)** is the industry-standard container orchestrator.

## Core Concepts

## Setting Up a Local Cluster

For development, use one of these tools:

```bash
# Docker Desktop (built-in, enable in settings)
# No command needed — toggle Kubernetes in Docker Desktop settings

# Or use minikube
minikube start

# Or use kind (Kubernetes in Docker)
kind create cluster
```

Verify the cluster:

```bash
kubectl cluster-info
kubectl get nodes
```

## Pods

A pod is defined in YAML:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: order-service
  labels:
    app: order-service
spec:
  containers:
    - name: order-service
      image: order-service:1.0
      ports:
        - containerPort: 8080
      env:
        - name: ASPNETCORE_ENVIRONMENT
          value: "Production"
```

You rarely create pods directly — Deployments manage them.

## Deployments

A Deployment ensures a desired number of pod replicas are running:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
    spec:
      containers:
        - name: order-service
          image: order-service:1.0
          ports:
            - containerPort: 8080
          resources:
            requests:
              memory: "128Mi"
              cpu: "100m"
            limits:
              memory: "256Mi"
              cpu: "500m"
```

## Services

A Service provides stable networking for pods:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: order-service
spec:
  selector:
    app: order-service
  ports:
    - port: 80
      targetPort: 8080
  type: ClusterIP
```

Other pods can now reach the order service at `http://order-service` (port 80).

### Service Types

| Type | Description |
|---|---|
| `ClusterIP` | Internal only (default). Other pods can reach it. |
| `NodePort` | Exposes on each node's IP at a static port. |
| `LoadBalancer` | Provisions an external load balancer (cloud providers). |

## Essential kubectl Commands

```bash
# Apply a configuration file
kubectl apply -f order-service.yaml

# List resources
kubectl get pods
kubectl get deployments
kubectl get services

# View pod logs
kubectl logs order-service-abc123

# Stream logs
kubectl logs -f order-service-abc123

# Describe a resource (debugging)
kubectl describe pod order-service-abc123

# Execute a command in a pod
kubectl exec -it order-service-abc123 -- bash

# Scale a deployment
kubectl scale deployment order-service --replicas=5

# Delete a resource
kubectl delete -f order-service.yaml
```

## Namespaces

Organize resources into logical groups:

```bash
# Create a namespace
kubectl create namespace microservices

# Deploy to a specific namespace
kubectl apply -f order-service.yaml -n microservices

# List pods in a namespace
kubectl get pods -n microservices

# Set a default namespace for kubectl
kubectl config set-context --current --namespace=microservices
```

## Rolling Updates

Kubernetes performs rolling updates by default — new pods start before old ones terminate:

```bash
# Update the image
kubectl set image deployment/order-service order-service=order-service:2.0

# Watch the rollout
kubectl rollout status deployment/order-service

# Roll back if something goes wrong
kubectl rollout undo deployment/order-service
```

## Best Practices

- **Always set resource requests and limits** on containers
- Use **Deployments** (not bare pods) so Kubernetes manages replicas and rollouts
- Use **labels and selectors** consistently to connect Deployments and Services
- Use **namespaces** to separate environments or teams
- Start with **ClusterIP** services for internal communication
- Use **`kubectl describe`** and **`kubectl logs`** as your primary debugging tools
