## The Dual-Write Problem

When a service saves to its database **and** publishes a message, two things can go wrong:

1. **Database saved, message lost** — the service crashes after the commit but before publishing.
2. **Message published, database failed** — the publish succeeds but the transaction rolls back.

Both result in inconsistency between the service's state and the events other services receive.

```csharp
// ❌ BAD: Dual-write — database and broker are separate systems
public async Task PlaceOrderAsync(Order order)
{
    await _db.Orders.AddAsync(order);
    await _db.SaveChangesAsync();          // Step 1: DB commit

    await _publisher.Publish(new OrderPlacedEvent  // Step 2: Publish
    {
        OrderId = order.Id
    });
    // What if the app crashes between Step 1 and Step 2?
}
```

## The Outbox Solution

Instead of publishing directly, write the event to an **outbox table** in the **same database transaction**. A separate process reads the outbox and publishes to the message broker.

```
┌──────────────────────────────────────┐
│ Single Database Transaction          │
│                                      │
│  1. INSERT INTO Orders (...)         │
│  2. INSERT INTO Outbox (...)         │
│                                      │
│  COMMIT                              │
└──────────────────────────────────────┘
        │
        ▼
┌──────────────────┐    publish    ┌──────────┐
│ Outbox Publisher  │ ──────────▶  │  Broker  │
│ (background job)  │              └──────────┘
└──────────────────┘
```

## The Outbox Table

```csharp
public class OutboxMessage
{
    public Guid Id { get; set; }
    public string Type { get; set; } = "";
    public string Payload { get; set; } = "";
    public DateTime CreatedAt { get; set; }
    public DateTime? ProcessedAt { get; set; }
}

// EF Core configuration
public class OutboxMessageConfiguration : IEntityTypeConfiguration<OutboxMessage>
{
    public void Configure(EntityTypeBuilder<OutboxMessage> builder)
    {
        builder.ToTable("Outbox");
        builder.HasKey(x => x.Id);
        builder.HasIndex(x => x.ProcessedAt)
            .HasFilter("[ProcessedAt] IS NULL");  // Index unprocessed messages
    }
}
```

## Writing to the Outbox

Save domain changes and outbox messages in one transaction:

```csharp
// ✅ GOOD: Single transaction — atomic write
public async Task PlaceOrderAsync(Order order)
{
    await _db.Orders.AddAsync(order);

    var @event = new OrderPlacedEvent
    {
        OrderId = order.Id,
        CustomerId = order.CustomerId,
        TotalAmount = order.Total,
        OccurredAt = DateTime.UtcNow
    };

    _db.OutboxMessages.Add(new OutboxMessage
    {
        Id = Guid.NewGuid(),
        Type = typeof(OrderPlacedEvent).AssemblyQualifiedName!,
        Payload = JsonSerializer.Serialize(@event),
        CreatedAt = DateTime.UtcNow
    });

    await _db.SaveChangesAsync();  // Both saved in one transaction
}
```

## The Outbox Publisher

A background service reads unprocessed outbox messages and publishes them:

```csharp
public class OutboxPublisher : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILogger<OutboxPublisher> _logger;

    public OutboxPublisher(IServiceScopeFactory scopeFactory, ILogger<OutboxPublisher> logger)
    {
        _scopeFactory = scopeFactory;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            await ProcessOutboxAsync(ct);
            await Task.Delay(TimeSpan.FromSeconds(5), ct);
        }
    }

    private async Task ProcessOutboxAsync(CancellationToken ct)
    {
        using var scope = _scopeFactory.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<OrderDbContext>();
        var publisher = scope.ServiceProvider.GetRequiredService<IPublishEndpoint>();

        var messages = await db.OutboxMessages
            .Where(m => m.ProcessedAt == null)
            .OrderBy(m => m.CreatedAt)
            .Take(20)
            .ToListAsync(ct);

        foreach (var message in messages)
        {
            try
            {
                var type = Type.GetType(message.Type)!;
                var @event = JsonSerializer.Deserialize(message.Payload, type)!;
                await publisher.Publish(@event, type, ct);

                message.ProcessedAt = DateTime.UtcNow;
                _logger.LogInformation("Published outbox message {Id} of type {Type}",
                    message.Id, message.Type);
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Failed to publish outbox message {Id}", message.Id);
            }
        }

        await db.SaveChangesAsync(ct);
    }
}
```

Register the background service:

```csharp
builder.Services.AddHostedService<OutboxPublisher>();
```

## MassTransit Built-In Outbox

MassTransit has a built-in transactional outbox that handles all of this for you:

```csharp
builder.Services.AddMassTransit(x =>
{
    x.AddEntityFrameworkOutbox<OrderDbContext>(o =>
    {
        o.UseSqlServer();          // or UsePostgres()
        o.UseBusOutbox();          // Enable the outbox
        o.QueryDelay = TimeSpan.FromSeconds(5);
    });

    x.UsingRabbitMq((context, cfg) =>
    {
        cfg.Host("rabbitmq");
        cfg.ConfigureEndpoints(context);
    });
});
```

## Best Practices

- **Always use the outbox pattern** when you need to write to a database and publish a message
- Publish from outbox **in order** (by `CreatedAt`) to preserve event ordering
- **Clean up processed messages** periodically to prevent the outbox table from growing
- **Consumers must be idempotent** — the outbox guarantees at-least-once delivery, not exactly-once
- Prefer **MassTransit's built-in outbox** for production workloads
