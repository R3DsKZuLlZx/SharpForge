## Containerizing a .NET Service

In this lesson you'll learn how to build production-quality Docker images for .NET applications. The key technique is the **multi-stage build**, which compiles your code in one stage and copies only the published output into the final image.

## Multi-Stage Dockerfile

```dockerfile
# Stage 1: Build
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src

# Copy csproj and restore (cached layer)
COPY ["OrderService/OrderService.csproj", "OrderService/"]
RUN dotnet restore "OrderService/OrderService.csproj"

# Copy everything and publish
COPY . .
WORKDIR /src/OrderService
RUN dotnet publish -c Release -o /app/publish --no-restore

# Stage 2: Runtime
FROM mcr.microsoft.com/dotnet/aspnet:9.0 AS runtime
WORKDIR /app
COPY --from=build /app/publish .

ENV ASPNETCORE_URLS=http://+:8080
EXPOSE 8080

# Run as non-root user
USER $APP_UID

ENTRYPOINT ["dotnet", "OrderService.dll"]
```

## Layer Caching Strategy

Docker caches each layer. If a layer hasn't changed, Docker reuses the cached version. Order your Dockerfile instructions from **least frequently changed** to **most frequently changed**:

```dockerfile
# 1. Base image (rarely changes)
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src

# 2. Project files and restore (changes when packages change)
COPY ["OrderService/OrderService.csproj", "OrderService/"]
RUN dotnet restore "OrderService/OrderService.csproj"

# 3. Source code (changes frequently)
COPY . .
RUN dotnet publish -c Release -o /app/publish --no-restore
```

By restoring packages *before* copying source code, you avoid re-downloading NuGet packages every time you change a `.cs` file.

## The .dockerignore File

Keep your Docker build context small by excluding unnecessary files:

```text
**/.git
**/bin
**/obj
**/node_modules
**/.vs
**/.idea
**/Dockerfile*
**/.dockerignore
*.md
*.sln
```

## Configuration with Environment Variables

.NET reads environment variables automatically through the configuration system. Use `ENV` in the Dockerfile or pass them at runtime:

```bash
# Set at build time (baked into image)
ENV ASPNETCORE_ENVIRONMENT=Production

# Pass at runtime (preferred for secrets)
docker run -d \
    -e "ConnectionStrings__OrderDb=Server=db;Database=orders;..." \
    -e "ASPNETCORE_ENVIRONMENT=Production" \
    -p 8080:8080 \
    order-service
```

## Health Checks in Docker

Add a health check so Docker knows when your service is ready:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD curl -f http://localhost:8080/health || exit 1
```

Or in your .NET app, add a health endpoint:

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddHealthChecks();

var app = builder.Build();
app.MapHealthChecks("/health");
app.Run();
```

## Solution with Multiple Services

For a solution with multiple microservices, structure your Dockerfile to build from the solution root:

```bash
MySolution/
├── docker-compose.yml
├── OrderService/
│   ├── OrderService.csproj
│   └── Dockerfile
├── InventoryService/
│   ├── InventoryService.csproj
│   └── Dockerfile
└── Shared/
    └── Shared.Contracts.csproj
```

Each Dockerfile builds from the solution root to resolve project references:

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src

COPY ["OrderService/OrderService.csproj", "OrderService/"]
COPY ["Shared/Shared.Contracts.csproj", "Shared/"]
RUN dotnet restore "OrderService/OrderService.csproj"

COPY . .
WORKDIR /src/OrderService
RUN dotnet publish -c Release -o /app/publish --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:9.0
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "OrderService.dll"]
```

Build from the solution root with the `-f` flag:

```bash
docker build -t order-service -f OrderService/Dockerfile .
```

## Best Practices

- **Always use multi-stage builds** — never ship the SDK in production
- **Copy `.csproj` files and restore first** for optimal layer caching
- **Run as non-root** — use the built-in `$APP_UID` user
- **Use specific image tags** — `aspnet:9.0`, not `aspnet:latest`
- **Add `.dockerignore`** to keep the build context small and fast
- **Add health checks** so orchestrators know your container is ready
