## Dealing with Errors Gracefully

Things go wrong. Users enter invalid data, files don't exist, network connections fail. **Exception handling** allows your program to respond to errors gracefully instead of crashing.


In this lesson, you'll learn how to catch, handle, and throw exceptions, making your applications more robust and user-friendly.


## What is an Exception?

An **exception** is an object that represents an error or unexpected situation. When something goes wrong, .NET "throws" an exception, which disrupts normal program flow.



```csharp
// Without exception handling, errors crash the program
int[] numbers = { 1, 2, 3 };
Console.WriteLine(numbers[10]);  // IndexOutOfRangeException - CRASH!

int result = 10 / 0;  // DivideByZeroException - CRASH!

string text = null;
Console.WriteLine(text.Length);  // NullReferenceException - CRASH!
```

## Try-Catch Blocks

Use <code>try-catch</code> to handle exceptions:



```csharp
try
{
    // Code that might throw an exception
    int[] numbers = { 1, 2, 3 };
    Console.WriteLine(numbers[10]);  // This throws!
}
catch (IndexOutOfRangeException ex)
{
    // Handle the specific exception
    Console.WriteLine($"Error: {ex.Message}");
}

Console.WriteLine("Program continues...");  // This still runs!
```



### Catching Multiple Exception Types


```csharp
try
{
    Console.Write("Enter a number: ");
    string input = Console.ReadLine();
    int number = int.Parse(input);
    int result = 100 / number;
    Console.WriteLine($"Result: {result}");
}
catch (FormatException)
{
    Console.WriteLine("That's not a valid number!");
}
catch (DivideByZeroException)
{
    Console.WriteLine("Cannot divide by zero!");
}
catch (Exception ex)  // Catches any other exception
{
    Console.WriteLine($"Unexpected error: {ex.Message}");
}
```

## The Exception Object

The caught exception object contains useful information:



```csharp
try
{
    int[] arr = { 1, 2, 3 };
    Console.WriteLine(arr[100]);
}
catch (Exception ex)
{
    // Common exception properties
    Console.WriteLine($"Message: {ex.Message}");
    Console.WriteLine($"Type: {ex.GetType().Name}");
    Console.WriteLine($"Source: {ex.Source}");
    Console.WriteLine($"Stack Trace: {ex.StackTrace}");
    
    // Inner exception (if this was caused by another exception)
    if (ex.InnerException != null)
    {
        Console.WriteLine($"Inner: {ex.InnerException.Message}");
    }
}
```

## The finally Block

The <code>finally</code> block always executes, whether an exception occurred or not. Use it for cleanup:



```csharp
StreamReader? reader = null;
try
{
    reader = new StreamReader("data.txt");
    string content = reader.ReadToEnd();
    Console.WriteLine(content);
}
catch (FileNotFoundException)
{
    Console.WriteLine("File not found!");
}
catch (IOException ex)
{
    Console.WriteLine($"IO Error: {ex.Message}");
}
finally
{
    // Always runs - perfect for cleanup
    reader?.Dispose();
    Console.WriteLine("Cleanup complete.");
}
```

### Using Statement (Better for Cleanup)

For objects that implement <code>IDisposable</code>, use the <code>using</code> statement instead:



```csharp
// The 'using' statement automatically disposes the resource
using (StreamReader reader = new StreamReader("data.txt"))
{
    string content = reader.ReadToEnd();
    Console.WriteLine(content);
}  // reader.Dispose() called automatically, even if exception!

// Modern C# - using declaration (no braces needed)
using StreamReader reader = new StreamReader("data.txt");
string content = reader.ReadToEnd();
// Disposed when variable goes out of scope
```


## Throwing Exceptions

You can throw exceptions to signal errors in your own code:



```csharp
void SetAge(int age)
{
    if (age < 0)
    {
        throw new ArgumentException("Age cannot be negative", nameof(age));
    }
    if (age > 150)
    {
        throw new ArgumentOutOfRangeException(nameof(age), "Age seems unrealistic");
    }
    
    // Valid age, continue...
}

// Usage
try
{
    SetAge(-5);
}
catch (ArgumentException ex)
{
    Console.WriteLine(ex.Message);  // Age cannot be negative (Parameter 'age')
}
```



### Re-throwing Exceptions


```csharp
try
{
    DoSomethingRisky();
}
catch (Exception ex)
{
    // Log the error
    Console.WriteLine($"Error logged: {ex.Message}");
    
    // Re-throw to let caller handle it too
    throw;  // Preserves original stack trace
    
    // DON'T do this (loses stack trace):
    // throw ex;
}
```

## Creating Custom Exceptions

Create your own exception types for domain-specific errors:



```csharp
// Custom exception class
public class InsufficientFundsException : Exception
{
    public decimal Balance { get; }
    public decimal AttemptedAmount { get; }
    
    public InsufficientFundsException(decimal balance, decimal attempted)
        : base($"Insufficient funds. Balance: {balance:C}, Attempted: {attempted:C}")
    {
        Balance = balance;
        AttemptedAmount = attempted;
    }
}

// Using the custom exception
class BankAccount
{
    public decimal Balance { get; private set; }
    
    public void Withdraw(decimal amount)
    {
        if (amount > Balance)
        {
            throw new InsufficientFundsException(Balance, amount);
        }
        Balance -= amount;
    }
}

// Handling it
try
{
    account.Withdraw(1000);
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine(ex.Message);
    Console.WriteLine($"You need {ex.AttemptedAmount - ex.Balance:C} more.");
}
```


## Exception Filters

C# 6+ allows filtering exceptions with the <code>when</code> keyword:



```csharp
try
{
    MakeHttpRequest();
}
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    Console.WriteLine("Resource not found!");
}
catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.Unauthorized)
{
    Console.WriteLine("Please log in first.");
}
catch (HttpRequestException ex)
{
    Console.WriteLine($"HTTP error: {ex.StatusCode}");
}

// Useful for logging without catching
try
{
    DoWork();
}
catch (Exception ex) when (LogException(ex))  // LogException returns false
{
    // Never enters here, but exception is logged
}

bool LogException(Exception ex)
{
    Console.WriteLine($"[LOG] {ex.Message}");
    return false;  // Don't catch, just log
}
```


## Best Practices


<div class="best-practices">
<div class="practice do">
<h4>✅ Do</h4>- Catch specific exceptions when possible- Use <code>finally</code> or <code>using</code> for cleanup- Include helpful messages when throwing- Log exceptions for debugging- Use <code>throw;</code> to re-throw (preserves stack trace)

</div>
<div class="practice dont">
<h4>❌ Don't</h4>- Catch <code>Exception</code> without good reason- Use exceptions for normal flow control- Swallow exceptions silently (empty catch)- Use <code>throw ex;</code> (loses stack trace)- Throw exceptions in constructors if avoidable

</div>
</div>


```csharp
// ❌ Bad: Empty catch block (swallowing exceptions)
try
{
    DoWork();
}
catch { }  // Error is hidden - bugs become impossible to find!

// ❌ Bad: Using exceptions for flow control
try
{
    int index = Array.IndexOf(items, searchItem);
    if (index == -1) throw new Exception("Not found");
}
catch { }  // Don't do this - just use the -1 return value!

// ✅ Good: Specific handling with logging
try
{
    DoWork();
}
catch (SpecificException ex)
{
    _logger.LogError(ex, "Work failed");
    throw;  // Re-throw if caller should handle it
}
```
