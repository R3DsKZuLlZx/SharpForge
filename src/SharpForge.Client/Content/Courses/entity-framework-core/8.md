## Eager Loading (Include)

Use `Include` to load related entities in the same query (JOINs); this makes data available immediately but may produce large queries—use selectively.

```csharp
// Load related data in the same query
var products = await context.Products
    .Include(p => p.Category)
    .ToListAsync();

// Multiple includes
var orders = await context.Orders
    .Include(o => o.Customer)
    .Include(o => o.Items)
    .ToListAsync();

// Nested includes
var orders = await context.Orders
    .Include(o => o.Items)
        .ThenInclude(i => i.Product)
            .ThenInclude(p => p.Category)
    .ToListAsync();
```

## Filtered Include

Filtered `Include` limits which related entities are loaded (useful to reduce payload); note support depends on provider/EF Core version.

```csharp
// Only load active products in each category
var categories = await context.Categories
    .Include(c => c.Products.Where(p => p.IsActive))
    .ToListAsync();

// Order included entities
var categories = await context.Categories
    .Include(c => c.Products.OrderBy(p => p.Name).Take(5))
    .ToListAsync();
```

## Explicit Loading

Explicit loading fetches related entities on demand via the context entry API, helpful when you need to load relations conditionally after the parent is loaded.

```csharp
// Load related data on demand
var product = await context.Products.FindAsync(id);

// Load reference navigation
await context.Entry(product)
    .Reference(p => p.Category)
    .LoadAsync();

// Load collection navigation
var category = await context.Categories.FindAsync(categoryId);
await context.Entry(category)
    .Collection(c => c.Products)
    .LoadAsync();

// Check if loaded
bool isLoaded = context.Entry(product)
    .Reference(p => p.Category)
    .IsLoaded;
```

## Lazy Loading

Enable lazy loading with proxies to load navigation properties on access—be cautious: it can trigger many small queries (N+1 problem).

```bash
dotnet add package Microsoft.EntityFrameworkCore.Proxies
```

```csharp
// Enable lazy loading
options.UseLazyLoadingProxies();

// Entities must use virtual navigation properties
public class Product
{
    public int Id { get; set; }
    public virtual Category Category { get; set; }  // virtual!
}
```

<div class="warning-box">
    <div class="warning-box-header"><span>⚠️ Warning</span></div>
    <p>Lazy loading can cause N+1 query problems! Prefer eager loading for predictable performance.</p>
</div>

## Split Queries

Use `AsSplitQuery()` when a single large JOIN query is expensive—EF Core will split it into multiple queries which can sometimes improve performance.

```csharp
// Default: single query with JOINs (can be slow)
var orders = await context.Orders
    .Include(o => o.Items)
    .ToListAsync();

// Split into multiple queries (can be faster)
var orders = await context.Orders
    .Include(o => o.Items)
    .AsSplitQuery()
    .ToListAsync();

// Configure globally
options.UseSqlServer(connectionString, o => o.UseQuerySplittingBehavior(
    QuerySplittingBehavior.SplitQuery));
```
