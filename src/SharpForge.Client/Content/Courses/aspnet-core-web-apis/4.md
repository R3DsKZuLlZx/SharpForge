## From Request to Object

Model binding is how ASP.NET Core converts raw HTTP request data — JSON bodies, route segments, query strings, and headers — into strongly typed C# objects. Understanding binding sources is key to writing clean, predictable endpoints.

## How Model Binding Works

When a request arrives, ASP.NET Core inspects your action method parameters and tries to populate them from the request:

```csharp
[HttpPut("{id}")]
public IActionResult Update(int id, UpdateProductRequest request)
{
    // id   ← bound from route segment
    // request ← bound from JSON body
    return Ok();
}
```

With the `[ApiController]` attribute, the framework infers the binding source automatically:
- **Complex types** (classes) → `[FromBody]`
- **Simple types** (int, string) in the route → `[FromRoute]`
- **Simple types** not in the route → `[FromQuery]`

## Binding Source Attributes

You can be explicit about where a value comes from:

```csharp
[HttpGet("{id}")]
public IActionResult Get(
    [FromRoute]  int id,
    [FromQuery]  bool includeDetails = false,
    [FromHeader(Name = "X-Request-Id")] string? requestId = null)
{
    // GET /api/products/5?includeDetails=true
    // Header: X-Request-Id: abc-123
    return Ok();
}

[HttpPost]
public IActionResult Create(
    [FromBody] CreateProductRequest request)
{
    // JSON body is deserialized into the request object
    return Ok();
}
```

## Data Transfer Objects (DTOs)

DTOs define the shape of data going in and out of your API. They decouple your public API contract from your internal domain models.

```csharp
// ❌ BAD: Exposing your entity directly
[HttpPost]
public IActionResult Create(Product product)
{
    // Clients can set Id, CreatedAt, internal flags...
    _db.Products.Add(product);
    _db.SaveChanges();
    return Ok(product);
}

// ✅ GOOD: Use separate request/response DTOs
[HttpPost]
public ActionResult<ProductResponse> Create(CreateProductRequest request)
{
    var product = new Product
    {
        Name = request.Name,
        Price = request.Price,
        Category = request.Category,
        CreatedAt = DateTime.UtcNow
    };

    _db.Products.Add(product);
    _db.SaveChanges();

    var response = new ProductResponse
    {
        Id = product.Id,
        Name = product.Name,
        Price = product.Price,
        CreatedAt = product.CreatedAt
    };

    return CreatedAtAction(nameof(GetById), new { id = product.Id }, response);
}
```

### Defining DTOs

```csharp
// Request DTO — what the client sends
public class CreateProductRequest
{
    public string Name { get; set; } = "";
    public string Description { get; set; } = "";
    public decimal Price { get; set; }
    public string Category { get; set; } = "";
}

// Response DTO — what the client receives
public class ProductResponse
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Description { get; set; } = "";
    public decimal Price { get; set; }
    public string Category { get; set; } = "";
    public DateTime CreatedAt { get; set; }
}

// Update DTO — may differ from Create
public class UpdateProductRequest
{
    public string Name { get; set; } = "";
    public string Description { get; set; } = "";
    public decimal Price { get; set; }
}
```

## JSON Serialization Options

ASP.NET Core uses `System.Text.Json` by default. You can configure its behavior in `Program.cs`:

```csharp
builder.Services.AddControllers()
    .AddJsonOptions(options =>
    {
        // Use camelCase for property names (default)
        options.JsonSerializerOptions.PropertyNamingPolicy =
            JsonNamingPolicy.CamelCase;

        // Include enum string values instead of numbers
        options.JsonSerializerOptions.Converters.Add(
            new JsonStringEnumConverter());

        // Ignore null properties in responses
        options.JsonSerializerOptions.DefaultIgnoreCondition =
            JsonIgnoreCondition.WhenWritingNull;
    });
```

## Mapping Between Models

For small projects, manual mapping is straightforward. For larger projects, consider a mapping library:

```csharp
// Manual mapping with extension methods
public static class ProductMappings
{
    public static ProductResponse ToResponse(this Product product)
    {
        return new ProductResponse
        {
            Id = product.Id,
            Name = product.Name,
            Description = product.Description,
            Price = product.Price,
            Category = product.Category,
            CreatedAt = product.CreatedAt
        };
    }

    public static Product ToEntity(this CreateProductRequest request)
    {
        return new Product
        {
            Name = request.Name,
            Description = request.Description,
            Price = request.Price,
            Category = request.Category,
            CreatedAt = DateTime.UtcNow
        };
    }
}

// Usage in a controller
[HttpGet("{id}")]
public ActionResult<ProductResponse> GetById(int id)
{
    var product = _repository.GetById(id);
    return product is null ? NotFound() : Ok(product.ToResponse());
}
```

## Best Practices

- Always use **DTOs** — never expose your database entities directly
- Use **separate DTOs** for create, update, and response operations
- Name DTOs clearly: `CreateProductRequest`, `UpdateProductRequest`, `ProductResponse`
- Keep DTOs in a dedicated `DTOs` or `Models` folder
- Let `[ApiController]` infer binding sources — only be explicit when needed
