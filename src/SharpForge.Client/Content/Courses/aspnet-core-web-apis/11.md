## Control Who Can Do What

Authorization determines whether an authenticated user has permission to perform a specific action. In this lesson, you'll learn role-based, claims-based, policy-based, and resource-based authorization strategies.

## Role-Based Authorization

The simplest approach — restrict access based on roles assigned to the user:

```csharp
[ApiController]
[Route("api/[controller]")]
[Authorize]  // Require authentication for all actions
public class AdminController : ControllerBase
{
    [HttpGet("dashboard")]
    [Authorize(Roles = "Admin")]  // Only Admins
    public IActionResult Dashboard() => Ok("Admin dashboard");

    [HttpGet("reports")]
    [Authorize(Roles = "Admin,Manager")]  // Admin OR Manager
    public IActionResult Reports() => Ok("Reports data");

    [HttpDelete("users/{id}")]
    [Authorize(Roles = "Admin")]
    public IActionResult DeleteUser(int id) => NoContent();
}
```

Roles are stored as claims in the JWT. When you generate the token, include the role:

```csharp
new Claim(ClaimTypes.Role, "Admin")
```

## Claims-Based Authorization

Claims are key-value pairs that describe the user. You can authorize based on any claim:

```csharp
// In Program.cs
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("EmailVerified", policy =>
        policy.RequireClaim("email_verified", "true"));

    options.AddPolicy("MinimumAge", policy =>
        policy.RequireClaim("date_of_birth"));
});

// In a controller
[HttpGet("verified-content")]
[Authorize(Policy = "EmailVerified")]
public IActionResult VerifiedContent() => Ok("Verified users only");
```

## Policy-Based Authorization

Policies let you combine multiple requirements into reusable, named rules:

```csharp
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("CanManageProducts", policy =>
    {
        policy.RequireAuthenticatedUser();
        policy.RequireRole("Admin", "ProductManager");
        policy.RequireClaim("department", "inventory");
    });

    options.AddPolicy("PremiumUser", policy =>
    {
        policy.RequireAuthenticatedUser();
        policy.RequireClaim("subscription", "premium");
    });
});
```

Apply policies with the `[Authorize]` attribute:

```csharp
[HttpPost]
[Authorize(Policy = "CanManageProducts")]
public ActionResult<Product> Create(CreateProductRequest request)
{
    // Only authorized product managers reach here
    return Ok();
}
```

## Custom Authorization Requirements

For complex logic, create custom requirements and handlers:

```csharp
// Define the requirement
public class MinimumAgeRequirement : IAuthorizationRequirement
{
    public int MinimumAge { get; }
    public MinimumAgeRequirement(int minimumAge) => MinimumAge = minimumAge;
}

// Implement the handler
public class MinimumAgeHandler
    : AuthorizationHandler<MinimumAgeRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        MinimumAgeRequirement requirement)
    {
        var dobClaim = context.User.FindFirst("date_of_birth");
        if (dobClaim is null)
            return Task.CompletedTask;  // Requirement not met

        var dob = DateTime.Parse(dobClaim.Value);
        var age = DateTime.Today.Year - dob.Year;

        if (age >= requirement.MinimumAge)
            context.Succeed(requirement);

        return Task.CompletedTask;
    }
}
```

Register it:

```csharp
builder.Services.AddSingleton<IAuthorizationHandler, MinimumAgeHandler>();

builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("AtLeast18", policy =>
        policy.Requirements.Add(new MinimumAgeRequirement(18)));
});
```

## Resource-Based Authorization

Sometimes you need to check if a user can access a *specific* resource (e.g., "can this user edit *this* document?"):

```csharp
public class DocumentAuthorizationHandler
    : AuthorizationHandler<OperationAuthorizationRequirement, Document>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        OperationAuthorizationRequirement requirement,
        Document resource)
    {
        var userId = context.User.FindFirstValue(ClaimTypes.NameIdentifier);

        if (requirement.Name == "Edit" && resource.OwnerId == userId)
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}
```

Use it in a controller:

```csharp
[HttpPut("{id}")]
public async Task<IActionResult> Update(
    int id, UpdateDocumentRequest request,
    [FromServices] IAuthorizationService authService)
{
    var document = await _repository.GetByIdAsync(id);
    if (document is null)
        return NotFound();

    var authResult = await authService.AuthorizeAsync(
        User, document, Operations.Edit);

    if (!authResult.Succeeded)
        return Forbid();

    // Update the document
    return NoContent();
}
```

## Best Practices

- Start with **role-based** authorization for simple scenarios
- Use **policies** when you need to combine multiple requirements
- Use **resource-based** authorization for "ownership" checks
- Prefer **policy names** over inline role strings for maintainability
- Always authorize at the **API layer** — don't rely on the UI to hide buttons
