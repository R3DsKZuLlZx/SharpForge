## Map URLs to Code

Routing determines how an incoming HTTP request is matched to a specific controller action. In this lesson, you'll learn how to define flexible URL patterns that map cleanly to your API endpoints.

## Attribute Routing Basics

ASP.NET Core Web APIs use **attribute routing**, where you place route templates directly on controllers and actions:

```csharp
[ApiController]
[Route("api/[controller]")]  // Base route: /api/products
public class ProductsController : ControllerBase
{
    [HttpGet]                  // GET /api/products
    public IActionResult GetAll() => Ok();

    [HttpGet("{id}")]          // GET /api/products/5
    public IActionResult GetById(int id) => Ok();

    [HttpPost]                 // POST /api/products
    public IActionResult Create() => Ok();

    [HttpPut("{id}")]          // PUT /api/products/5
    public IActionResult Update(int id) => Ok();

    [HttpDelete("{id}")]       // DELETE /api/products/5
    public IActionResult Delete(int id) => Ok();
}
```

The `[controller]` token is replaced by the class name minus the "Controller" suffix. So `ProductsController` becomes `products`.

## Route Parameters

Route parameters are placeholders in the URL template that capture values from the request path:

```csharp
[HttpGet("{id}")]
public ActionResult<Product> GetById(int id)
{
    // id is automatically parsed from the URL segment
    var product = _repository.GetById(id);
    return product is null ? NotFound() : Ok(product);
}

// Multiple route parameters
[HttpGet("{category}/{id}")]
public ActionResult<Product> GetByCategoryAndId(string category, int id)
{
    // /api/products/electronics/42
    // category = "electronics", id = 42
    return Ok();
}
```

## Route Constraints

Route constraints restrict which values a route parameter will accept. If a request doesn't match, ASP.NET Core returns 404 instead of calling your action with bad data.

```csharp
// Only matches when id is an integer
[HttpGet("{id:int}")]
public IActionResult GetById(int id) => Ok();

// Only matches when slug contains letters, hyphens, etc.
[HttpGet("{slug:regex(^[a-z0-9-]+$)}")]
public IActionResult GetBySlug(string slug) => Ok();
```

## Query String Parameters

Parameters that aren't in the route template are automatically bound from the query string:

```csharp
[HttpGet]
public ActionResult<IEnumerable<Product>> GetAll(
    string? category = null,
    decimal? minPrice = null,
    decimal? maxPrice = null,
    int page = 1,
    int pageSize = 10)
{
    // GET /api/products?category=electronics&minPrice=50&page=2
    var query = _products.AsQueryable();

    if (category is not null)
        query = query.Where(p => p.Category == category);

    if (minPrice.HasValue)
        query = query.Where(p => p.Price >= minPrice.Value);

    if (maxPrice.HasValue)
        query = query.Where(p => p.Price <= maxPrice.Value);

    var results = query
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .ToList();

    return Ok(results);
}
```

## Combining Route and Query Parameters

A common pattern is to use route parameters for resource identity and query parameters for filtering or options:

```csharp
// Route param for identity, query params for options
[HttpGet("{id}")]
public ActionResult<Product> GetById(
    int id,
    bool includeReviews = false)
{
    // GET /api/products/5?includeReviews=true
    var product = _repository.GetById(id);
    if (product is null)
        return NotFound();

    if (includeReviews)
        product.Reviews = _reviewRepository.GetForProduct(id);

    return Ok(product);
}
```

## Custom Route Prefixes

You can override or extend the class-level route on individual actions:

```csharp
[ApiController]
[Route("api/[controller]")]
public class ReportsController : ControllerBase
{
    [HttpGet("daily")]        // GET /api/reports/daily
    public IActionResult DailyReport() => Ok();

    [HttpGet("weekly")]       // GET /api/reports/weekly
    public IActionResult WeeklyReport() => Ok();

    [HttpGet("/status")]      // GET /status (absolute path, ignores prefix)
    public IActionResult Status() => Ok("Running");
}
```

A leading `/` in the action route makes it absolute, bypassing the controller prefix entirely. Use this sparingly.

## Best Practices

- Use **plural nouns** for resource names: `/api/products`, not `/api/product`
- Keep URLs **lowercase** and use **hyphens** for multi-word segments: `/api/order-items`
- Use **route constraints** to fail fast on invalid input
- Reserve **query strings** for optional filtering, sorting, and pagination
- Avoid deeply nested routes — two levels is usually enough
