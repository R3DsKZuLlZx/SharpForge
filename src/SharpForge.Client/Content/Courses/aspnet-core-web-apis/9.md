## Fail Gracefully

Proper error handling is essential for a production API. In this lesson, you'll learn how to handle errors consistently, return standardized responses, and avoid leaking internal details to clients.

## The Problem

Without centralized error handling, you end up with inconsistent responses and try-catch blocks scattered everywhere:

```csharp
// ❌ BAD: Try-catch in every action
[HttpGet("{id}")]
public async Task<IActionResult> GetById(int id)
{
    try
    {
        var product = await _repository.GetByIdAsync(id);
        if (product is null)
            return NotFound();
        return Ok(product);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error getting product {Id}", id);
        return StatusCode(500, "An error occurred");
    }
}
```

## Problem Details (RFC 7807)

ASP.NET Core supports the **Problem Details** standard out of the box. Enable it in `Program.cs`:

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddProblemDetails();
builder.Services.AddControllers();

var app = builder.Build();

app.UseExceptionHandler();
app.UseStatusCodePages();

app.MapControllers();
app.Run();
```

This produces standardized error responses:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Not Found",
  "status": 404,
  "detail": "Product with ID 42 was not found.",
  "instance": "/api/products/42"
}
```

## Custom Exception Types

Define exceptions that map to HTTP status codes:

```csharp
public abstract class ApiException : Exception
{
    public int StatusCode { get; }

    protected ApiException(string message, int statusCode)
        : base(message)
    {
        StatusCode = statusCode;
    }
}

public class NotFoundException : ApiException
{
    public NotFoundException(string message)
        : base(message, StatusCodes.Status404NotFound) { }

    public NotFoundException(string entity, object id)
        : base($"{entity} with ID '{id}' was not found.",
               StatusCodes.Status404NotFound) { }
}

public class ConflictException : ApiException
{
    public ConflictException(string message)
        : base(message, StatusCodes.Status409Conflict) { }
}

public class ForbiddenException : ApiException
{
    public ForbiddenException(string message)
        : base(message, StatusCodes.Status403Forbidden) { }
}
```

Now your services can throw meaningful exceptions:

```csharp
public class ProductService : IProductService
{
    public async Task<Product> GetByIdAsync(int id)
    {
        var product = await _db.Products.FindAsync(id);
        return product ?? throw new NotFoundException("Product", id);
    }

    public async Task<Product> CreateAsync(CreateProductRequest request)
    {
        var exists = await _db.Products
            .AnyAsync(p => p.Name == request.Name);

        if (exists)
            throw new ConflictException(
                $"A product named '{request.Name}' already exists.");

        // ... create the product
    }
}
```

## Global Exception Handler (IExceptionHandler)

In .NET 8+, use the `IExceptionHandler` interface for structured exception handling:

```csharp
public class GlobalExceptionHandler : IExceptionHandler
{
    private readonly ILogger<GlobalExceptionHandler> _logger;

    public GlobalExceptionHandler(ILogger<GlobalExceptionHandler> logger)
    {
        _logger = logger;
    }

    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext,
        Exception exception,
        CancellationToken cancellationToken)
    {
        _logger.LogError(exception, "Unhandled exception: {Message}",
            exception.Message);

        var (statusCode, title) = exception switch
        {
            ApiException api => (api.StatusCode, exception.Message),
            _ => (StatusCodes.Status500InternalServerError,
                  "An unexpected error occurred.")
        };

        httpContext.Response.StatusCode = statusCode;

        await httpContext.Response.WriteAsJsonAsync(new ProblemDetails
        {
            Status = statusCode,
            Title = title,
            Instance = httpContext.Request.Path
        }, cancellationToken);

        return true;
    }
}
```

Register it in `Program.cs`:

```csharp
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
builder.Services.AddProblemDetails();

var app = builder.Build();

app.UseExceptionHandler();
```

## Clean Controllers

With global exception handling, your controllers become clean and focused on the happy path:

```csharp
// ✅ GOOD: No try-catch — exceptions are handled globally
[HttpGet("{id}")]
public async Task<ActionResult<ProductResponse>> GetById(int id)
{
    var product = await _productService.GetByIdAsync(id);
    return Ok(product.ToResponse());
}

[HttpPost]
public async Task<ActionResult<ProductResponse>> Create(
    CreateProductRequest request)
{
    var product = await _productService.CreateAsync(request);
    return CreatedAtAction(nameof(GetById),
        new { id = product.Id }, product.ToResponse());
}
```

## Best Practices

- Use **Problem Details** (RFC 7807) for all error responses
- Implement a **global exception handler** — avoid try-catch in controllers
- Create **custom exception types** that map to HTTP status codes
- **Log all exceptions** with sufficient context for debugging
- Return **generic messages** in production, **detailed messages** in development
